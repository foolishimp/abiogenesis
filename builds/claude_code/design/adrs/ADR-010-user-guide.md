# ADR-010: User Guide — Structure and Acceptance Criteria

**Status**: accepted
**Date**: 2026-03-15
**Covers**: REQ-F-DOCS-001

## Decision

`builds/claude_code/README.md` is the user guide. It must cover three sections:

1. **Installation** — `gen-install <target>` walkthrough; prerequisites
2. **First session** — step-by-step: intent → requirements → feature decomp → design → code → tests
3. **Operating loop** — reference for gen-start, gen-iterate, gen-gaps, gen-review commands

A smoke test in `builds/claude_code/tests/test_docs.py` asserts the README exists
and contains the three section headers, keeping the doc honest without prescribing prose.

## Rationale

- Docs are a deliverable, not an afterthought — they have a feature vector and a test
- The three-section structure mirrors the natural on-boarding path: install → first use → daily use
- Testing for section presence (not content) is the minimum viable doc gate

## Consequences

- `README.md` is part of the `builds/claude_code/` deliverable
- `test_docs.py` carries `# Validates: REQ-F-DOCS-001`
- README prose is not generated by the engine — written by the agent at the docs edge
