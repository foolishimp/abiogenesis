## Intake Triage

1. **Demand**: A calling agentic builder must invoke the published Consensus
   GraphFunction over a ticket or other typed subject and receive attributed
   agreement, dissent, ruling, result, lineage, and replay truth.
2. **Observed defect**: the prior realization placed the constructive body in
   a Consensus-specific TypeScript plugin. It was not a graph and was reverted.
3. **Smallest re-entry**: current product and requirements already require the
   bounded feature. The missing authority is the lawful realization design and
   compiler probe, so this ticket is one `design_reframe`.
4. **Probability and proportionality**: the material risk is another category
   error hidden behind working systems code. The proportionate hedge is one
   reviewed domain/sequence/state design plus a no-effects compiler probe. This
   ticket adds no hostile-desktop hardening, scheduler, service framework, or
   feature-specific engine law.

## Singular Boundary

This ticket owns exactly one result: the canonical Consensus GTL body and its
exact first compiler gap census. It does not realize any reported gap. The
current design pass has already found a pre-admission gap: the native
`fan_out(graphFunction, over)` facade preserves one same-node vector boundary
and therefore cannot type the required
`ReviewerAssignmentVector -> AttributedFindingsVector`
relation. T-252 must stop before body authorship until that generic HOF relation
is expressible and compiler-visible; a hand-built name/tag or `promote`
workaround is non-closure.

The body shall preserve these category distinctions:

- GTL `fan_out`/`fan_in` express reviewer-vector topology;
- GTL `recurse(graphFunction, termination, foldback)` expresses another
  semantic verification round;
- `workflow.C` is the named lift of a child GraphFunction at a parent C-call
  boundary;
- `C.batch` is an ordered compute-task grouping only where the compiler can
  prove its relation to the explicit reviewer vector;
- `C.retry` is same-contract retry under the declared retryable-failure
  allowlist only. It shall never implement `recurse_next_round`;
- the submitting actor identity never selects the submitter-response worker.
  A separate declared submitter role/worker-selection, instruction-contract,
  result-contract, capability, and configuration binding owns that F_P turn;
- each reviewer profile owns its own role-or-worker-selection contract.
  Ordinary ABG selection resolves it to a worker assignment, and backend and
  transport derive from that assignment. No panel-global agent contract or
  independently selected backend/transport is lawful. The authored GTL
  assignment carries only the selection-contract ref; concrete worker,
  backend, and transport identity remain ABG runtime truth;
- initial semantic assessment and post-submitter semantic reassessment are
  distinct native carriers. Only the post-submitter carrier, joined to the
  exact admitted submitter-response ref, may route to `recurse_next_round`;
- every helper GraphFunction is module-local. This bounded feature does not
  publish the reserved `gtl://abg/review/*` nameplates as a generic Review
  product;
- the canonical outer target is `ConsensusResult`. A round-outcome target is
  an internal relation and cannot satisfy the public GraphFunction contract;
- ABG owns GraphCall/frame/C-call execution, admission, continuation, events,
  replay, and closure; and
- `escalate_fh` is typed stop truth through the ordinary F_H boundary, not a
  plugin label or a synthesized human ruling.

The compiler output, not this ticket's expectation, determines which language,
compiler, execution-basis, or runtime gaps are real.

## Execution After Design Acceptance

1. Re-run the native HOF construction check for the accepted assignment-vector
   to findings-vector relation. If the published typed API still
   preserves only same-node input/output, retain the authoring gap and stop;
   route one singular generic HOF design/realization owner before resuming this
   ticket.
2. Once that generic prerequisite closes, author one canonical pure-data GTL module rooted at
   `graph-function://abg/consensus/submitter-reviewer-rounds` with the topology
   fixed by the accepted design.
3. Use native GTL constructors to the maximum extent, serialize canonically,
   and admit the serialized root through raw GTL admission.
4. Attach only declared C programs and named child GraphFunction refs. Do not
   add a plugin, service, shell loop, test-only interpreter, or local prompt
   renderer. The one reviewer-turn program must contain `C.retry` with positive
   budget `2` and the standard ABG retryable-failure allowlist.
5. Run the admitted root through the existing semantic compiler before any
   runtime invocation.
6. Compare every relied-on GTL and C constructor with the compiler's runtime
   realization census. Current `recurse`, `fan_out`, and `fan_in` declarations
   are not runtime-consumed and do not receive semantic gaps from the current
   compiler; silent acceptance must be recorded as a compiler-coverage gap.
7. Because the current nested C compiler stops at the outer unrealized wrapper,
   derive a deterministic probe manifest from the unchanged admitted body and
   compile each relied-on nested term at its original body path. A fail-fast
   full-root result is not the exact census. The manifest may extract terms; it
   may not rewrite, flatten, omit, or replace them.
   Treat the ordered diagnostics as a frontier census: realizing one outer atom
   may remove its gap while exposing previously unreachable inner gaps. Gap
   count is not required to decrease monotonically; path-addressed coverage is.
8. Persist the exact canonical-body digest, probe-manifest digest, and ordered
   diagnostic census,
   including classification, diagnostic identity, path, requirement/axiom
   refs, evidence refs, and repair affordances.
9. Prove the probe emitted no worker invocation, event, result, replay, archive,
   workspace mutation, or product artifact.
10. Route each retained gap to a singular successor design ticket. Reuse the
   exact body digest as the recompile oracle; atom work may change compiler and
   runtime output, never the Consensus body to accommodate an implementation.

## Closure Conditions

1. F_H accepts the referenced three-view design after axiom review.
2. One executable Consensus GTL body exists as admitted canonical data under
   the required SYSTEM-owned identity; a declaration nameplate is insufficient.
   This condition cannot be attempted through the current same-node `fan_out`
   facade; the generic typed HOF relation must close first.
3. Native authoring and raw admission accept the same body. Any typed
   invalid-program relation is retained as rework evidence and keeps this
   ticket open; no cast or loose JSON bypasses it.
4. The existing ABG semantic compiler runs over the admitted root and an exact,
   deterministic diagnostic census is checked against the body digest.
5. The census distinguishes invalid authored structure from lawful but
   unrealized semantics and identifies missing compiler diagnostics as defects.
6. The probe is effect-free and does not attempt runtime execution while any
   relied-on constructor is unrealized.
7. `recurse_next_round` is represented only by GTL recursion with declared
   termination and foldback. The body also contains `C.retry` only around one
   reviewer F_P call, with positive budget `2` and the standard
   `transport_failure | no_output | contract_failure` allowlist. It never
   stands for a semantic round.
8. The body accepts a non-empty explicit reviewer vector without hard-coding
   the release fixture's two-profile cardinality. Native and raw carriers
   preserve distinct assignment-vector input and findings-vector
   output types without `promote`, name-prefix, tag, cast, or hand-built wrapper
   coercion. Each profile independently resolves its declared execution-
   selection contract through ordinary ABG worker selection. The resolved
   worker assignment is ABG-owned runtime truth and the only authority from
   which backend and transport derive; it is not stored in the authored GTL
   assignment. A shared panel agent contract or second backend selector is
   non-closure.
9. Submitter-response execution resolves through an explicit role and worker-
   selection contract with instruction/result refs; it is never inferred from
   the subject's submitting actor, CLI caller, or current agent. The round
   policy also binds the semantic reducer/reassessor's exact role/worker,
   configuration digest, instruction/result contracts, and capabilities; no
   ambient or default F_P reducer is lawful. Its F_H interaction binding also
   joins the exact Consensus invocation/round/subject to declared interaction
   and result contracts and capabilities; no ambient approval subject is
   lawful.
10. The public callable/read contract is `ConsensusResult`. On graph success,
    only `closed_done` reaches the outer output projection; internal
    `recurse_next_round` outcomes are nested and cited but never terminal.
    `escalate_fh` plus interaction ref and typed contract failure are public
    result variants replay-derived from ordinary F_H-held and C-call-blocked
    truth. Neither path advances to project-result or fabricates a fourth round
    outcome.
11. Module-local reviewer/reducer/submitter helpers do not create a generic
    Review catalog product.
12. Every relied-on constructor has both compiler coverage and a runtime
    realization row. Silent acceptance of declaration-only `recurse`,
    `fan_out`, or `fan_in` is a retained blocking gap, not a pass.
13. Nested fail-fast behavior cannot hide inner gaps: the census includes one
   deterministic subprobe for every relied-on unrealized wrapper or admissible
   executable subterm at its canonical body path and reconciles them with the
   full-root result. A non-standalone term is recorded as a compiler-
   observability gap rather than coerced into an invalid program. The census is
   frontier-shaped: closing an outer gap may expose inner gaps, so diagnostic
   count is never used as a monotone progress measure.
14. Each compiler gap has one singular successor owner; no gap is repaired in
    this ticket and no Consensus-specific runtime atom is proposed.
15. Every reviewer, semantic-reducer, submitter-response, and reassessment F_P
    output crosses its selected result-contract admission before routing. Any
    malformed, unattributed, nonretryable, or retry-exhausted output takes the
    existing ABG C-call blocked path and cannot reach panel fan-in, semantic
    routing, closure, foldback, or a round outcome. The public
    `ConsensusResult` contract-failure branch is a replay-derived read
    projection of that blocked invocation, not a graph-success value.
16. F_D emits only envelope, attribution, cardinality, and exact-equality
    facts. F_P owns semantic agreement, dispute, dissent, and rulings.
17. Initial reduction admits an `InitialSemanticAssessment`; reassessment after
    the exact admitted submitter response admits a distinct
    `PostSubmitterSemanticAssessment` that retains that response ref. Only the
    post-submitter type may reach foldback. An initial assessment cannot type a
    direct recurse edge.

## Non-Closure Conditions

- The candidate design exists but has not received F_H acceptance.
- Only the existing catalog declaration or reserved vocabulary exists.
- The panel body lives in TypeScript, a plugin, handler, service, CLI, shell,
  script, fixture, or prompt template.
- A fixed two-reviewer tuple is presented as the generic panel contract.
- The body is hand-constructed around the current same-node `fan_out` facade,
  or a name/tag/`promote` convention is used to pretend assignments became
  findings.
- Worker completion order determines reviewer attribution or reduction order.
- Reviewer profiles inherit one ambient or panel-global agent contract, or GTL
  independently selects a backend/transport outside the admitted worker
  assignment.
- An authored reviewer assignment stores a concrete runtime worker/backend/
  transport identity, or an initial assessment reaches `recurse_next_round`
  without the exact submitter-response and post-submitter reassessment join.
- `C.retry` or an engine retry attempt represents a semantic verification
  round.
- Malformed, unattributed, or retry-exhausted reviewer, reducer, submitter, or
  reassessment output reaches routing/fan-in or is represented as another round
  outcome.
- F_D infers semantic agreement, dissent, or ruling meaning from reviewer
  outputs.
- An ordinary pending F_H C-call returns `escalate_fh` as graph-success data or
  advances to a downstream result-projection C program.
- The probe compiles by omitting a required child function, vector boundary,
  foldback relation, output branch, or contract identity.
- The outer target remains `contract://abg/consensus/round-outcome` rather than
  the canonical Consensus result contract.
- A submitter response runs as the caller/current agent without a separately
  admitted role, worker-selection, instruction, and result binding.
- Reserved Review nameplates are promoted as public helpers or treated as a
  separately delivered generic Review product.
- A missing semantic-compiler diagnostic is treated as successful execution.
- Only the outermost fail-fast diagnostic is recorded while nested relied-on
  terms remain unprobed.
- This ticket edits generic C runtime behavior, execution-basis law, F_P/F_H
  public operations, schemas, publication, installed scenarios, or release
  evidence.
