## Root Cause

The F_D check scripts (generated by helpers) and the agent prompts do not share a
constitutional requirement surface defining the output format. Each side drifted
independently:

| Check script expects | Agent actually produces |
|---------------------|------------------------|
| `# REQ-NNN` (level-1 heading) | `## REQ-NNN Title` (level-2 heading) |
| `**Status**: Draft` inline metadata | `\| Status \| Draft \|` table row |
| `**REQ-NNN-001**:` AC format | `**REQ-NNN-AC-01** —` AC format |
| `### Component: Name` per component | `- **Name** —` bullet under `## Components` |

ABG 1.0 is the released product. The agent's observed output is the authoritative
format reference for the 1.x line. Fix the check scripts to match; update prompts
to specify format explicitly so future runs remain stable.

## SPEC_METHOD note

Under SPEC_METHOD this would eventually be resolved by writing REQ-FORMAT-* requirement
families that both agent prompts and check scripts derive from. That is B-010 scope
(ABG 2.0 induction). For 1.x, the correct action is `realization_refactor`: align
the check scripts and prompts to released agent behavior with no upstream drift.

## Changes

### helpers_intent_requirements.py
- `requirements_checker_script()`: update heading regex `^# ` → `^## `, metadata
  checks from inline `**Field**:` to table `| Field |`, AC regex from
  `REQ-NNN-\d{3}**:` to `REQ-NNN-AC-\d{2}**` (no trailing colon)
- `judge_intent_traceability()`: same heading regex fix
- `intent_requirements_artifact()`: update fixture to match new format
- `output_contract_text`: add explicit format spec so agent knows to use `## REQ-NNN`
  headings, table metadata, `**REQ-NNN-AC-NN** —` AC format
- `standard_text`: add format line

### helpers_gsdlc_lite.py
- `design_checker_script()`: replace `^### Component:` regex with scoped bullet count
  under `## Components` section
- `judge_design_quality()`: same fix
