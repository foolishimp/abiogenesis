## Context

`T-009`, `T-010`, and `T-011` closed GTL declaration, GTL publication, and the
first ABG runtime steel thread.

That makes the next lawful wave `M04-app-bootstrap`, not more kernel widening.

The public package entry now needs its own bounded migration because `M04` owns:

- app-facing orchestration services
- operator-facing entry boundary
- configured worker/runtime identity projection
- public event and assessment ingress over kernel truth

Without a separate `M04` execution contract, the TypeScript line would risk
recreating the same drift family at the public runtime boundary that `T-011`
prevented in the kernel.

## Triage Position

This is not a requirement reprice and not a whole-app port ticket.

The constitutional product truth and the completed `M03` kernel truth already
exist.
The lawful re-entry is the TypeScript `M04` design surface above the completed
kernel.

The first `M04` issue is:

- the package layer still has no explicit public start carrier boundary
- configured runtime or worker identity projection has not yet been realized in
  the TypeScript line
- the public entry must stay a steel thread rather than silently widening into
  auto loops, proxy approval doctrine, sandbox harnesses, or downstream
  projections
