## Verdict

The repair direction is right and the first construction is a real, type-clean
compaction inside the existing owners: a file body is born inline once in the
Result that admits its context, every later same-Run handoff carries an exact
admitted-member reference, identity is the physical facts only, and the
resolver fails closed with seven typed causes. No new store, service, registry
or second event stream was added. The native Testing red is two defects, both
reproduced here without a model: a stale C2 source pin outside the write grant,
and one test-fixture line. Everything else in the red is downstream of the pin.

Unproved: no post-repair runtime has executed. The only measurement is a
structural fixture. The retained-route copy still duplicates every body birth
once. The identity formula changed under an unchanged schema version, so every
pre-repair context fails validation under the new code with no declared
disposition. The two constructions took opposite approaches on the pin seam and
the live worksite holds the weaker one.

Is this becoming a practical single-machine system? Yes, one bounded cut away.
The proposed 53-path completion is about ten times larger than what the
evidence requires.

## Findings, ranked by likelihood and harm

### F1. Stale C2 source pin outside the grant (S2, certain, blocks the C2 gate)

- Coordinate: `gtl/worksite_command_execution.ts:36–39` pins
  `build/code/src/product/worksite_command_execution.js` at
  `sha256:9c5716a1…`, `byteCount: 118675`; the first construction edits that
  renderer (`nativeReacquisitionBody`, identity-entry compare, patched line
  378); `scripts/generate-product-manifest.mjs:102` refuses.
- Trigger and consequence: `npm run build` fails; the package step
  (`scripts/refresh-candidate-basis.mjs`) never runs, so
  `product-toolchain-manifest.json` and `test_env/fixtures/abi5-root-candidate-basis.json`
  are absent in the C2 sandbox (the fixture is not among the 963 snapshot
  members; it is regenerated by the package step). Result: 16 focused, 2
  artifact and 1 affected lane fail with ENOENT, not with a Product defect.
- Root cause and why missed: the 46-path write bound was derived from the
  consumer census, not from the manifest's pinned-member list. The pin path was
  ungranted, so the second construction reverted the renderer and moved the
  relation into `abg/native_work_reacquisition.ts` (`inSourceContextCarriage`).
- Reproduced: subject (first) build refused with the same message; subject2
  (second) builds, generates the manifest and the candidate basis, and runs the
  two owner lanes 55/57 (the one red is F2).
- Smallest repair: re-enter the pin (one line pair plus regenerated manifest)
  and keep the first construction's identity-entry compare; delete
  `inSourceContextCarriage`. Proof: build, package, focused, affected and
  artifact lanes green except declared skips.

### F2. Test fixture passes a mutable slice as a prefix snapshot (S3, certain)

- Coordinate: `test_env/tests/t287-event-body-encoding.test.mjs:603`
  (`selectValidatedRuntimeEventPrefix(events.slice(…))`). `readAll()` returns a
  `RuntimeDerivationSource` snapshot (`event_store.ts:2520–2524`); a slice is a
  plain array; `event_prefix.ts:477/485` throws.
- Consequence: the lane "native context bodies are born inline once…" aborts

  tampered ×4, stale, foreign ×2, denied ×2, missing, inline-tamper,
  foreign-holder and cold-reconstruction legs of the resolver are unexecuted.
- Repair: `validatedRuntimeEventPrefixBeforeEvent(prefix, changed.event.eventId)`
  as the amendment names. Proof: the lane passes and asserts all seven codes.

### F3. Identity formula changed under the same schema version (S2 design, high likelihood on any cold read of pre-repair history)

- Coordinate: `product/worksite_effect.ts` `worksiteContextIdentityDigest`
  (bytes excluded) with `schemaVersion: "5.0.0"` unchanged
  (`worksite_operations.ts:1169`); `abg/instruction_assembly.ts:178` drops
  `task` from the native-work envelope.
- Consequence: every pre-repair `worksite_context_observation` (B11 log
  1,339,885,116 B; the P1 Run's own 1,365,770,962 B log; the pinned
  `ABI5_NATIVE_OBSERVATION_CAPTURE` fixture at `t287-default-library.test.mjs:788–800`)
  fails `isWorksiteContextObservation` by digest mismatch with no discriminator;
  historical transport bindings differ from recomputed envelopes.
- Why missed: the only lane that validates a captured pre-repair context is
  opt-in by environment variable; no lane feeds an old context to the new guard.
- Repair: declare the boundary (RC3 reads no pre-repair Run history as
  validated values) in the design and release note and make the cold path
  refuse with a typed cause, or bump the context `schemaVersion`. One lane
  either way. Acceptable for a one-machine development candidate once declared;
  not acceptable silently (PRODUCT 1268: inherited redundancy affecting
  currentness or replay is a correctness defect).

### F4. The retained route copy still duplicates every birth once (S2 efficiency, certain by code, unmeasured)

- Coordinate: `abg/event_body_encoding.ts:22–24` gives body slots only to
  `basis_admitted`, `c_call_result_admitted` and
  `actor_transport_binding_admitted`; `abg/traversal_route.ts:4319`
  (`constructRetainedGraphInput(executionBasis.rawInputValue, result.value)`)
  writes the whole source Result value inline in `traversal_route_admitted`.
- Consequence: after P1 the selector Result's birth (about 39 MB per context in
  the B11 shape) is copied once more by the following route event. B11
  measured 361,529,670 B in 28 route events. Predicted post-repair closed log:
  about two births plus changed bytes plus metadata, roughly 80 to 90 MB from
  1.34 GB. Not measured.
- Smallest repair: a slot for `traversal_route_admitted` over
  `payload.input.value.source` so the existing first-inline/back-reference
  codec shares the Result value physically; no contract change. Do it only if
  the matched run (F5) shows the route family at or above one birth.

### F6. Two constructions, two answers on one seam (S3 design, churn risk)

- The first compares physical facts in the request contract (renderer edit,
  pin stale). The second keeps the renderer and presents the fresh context in
  the source `after` carriage (`native_work_reacquisition.ts`
  `inSourceContextCarriage`). In a replacement Run that request then carries
  member references the Run's own resolver refuses as `foreign`
  (`event_prefix.ts:939`). Harmless today because C2 resolves no body, but a
  value whose declared carriage is unreadable in its own Run exists only to
  avoid the pin. The live worksite holds this version. The P1-02 proposal
  re-enters the pin, which makes the workaround dead code. Decide once.

### F7. P1-02 scope is disproportionate (Q7)

- Causally required: the pin (1 path), the fixture line (1), regenerated
  manifest, design sentences. Optional after measurement: the route slot (1).
- Not required now: replacing the exact-equality owners
  (`native_worksite_execution.ts:83–107`, `execution_basis.ts:747–750`,
  `worksite_command_execution.ts:420`, `native_work_reacquisition.ts:76`,
  `default_library.ts:332`) with coordinate comparisons. These values are now
  metadata-sized; the pre-repair cost was 224 ms for a 124 MB value. The
  replacement must compare the admitted coordinate, never a bare digest
  (PRODUCT handoff law: equal bytes do not establish producer identity), so
  it carries identity risk for no measured gain.
- Not required now: cross-Run holder reuse (`event_prefix.ts:891/939`). A
  replacement Run re-births its first context once; cold acquisition retains
  reconstruction (PRODUCT 818–824). Allowing it needs the lineage owner to
  authenticate the predecessor Run, a design decision, not a completion item.
- No registry, service or framework is needed; none was added.

### F8. Hygiene (S4)

- Admission checks member shape only; an unresolvable member is discovered at
