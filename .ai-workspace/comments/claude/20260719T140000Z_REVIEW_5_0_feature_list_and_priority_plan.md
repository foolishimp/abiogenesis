## P1 — the baseline-conservation owner is missing (will block at priority 14)

Searched every active ticket and the full T-244 register: **nothing owns the
RC5 reconciliation** — the postmortem's restart condition 3 ("reconcile the
ten RC5-side commits… no silent drop"), the decisively-verified
`worker_executes` lane-law loss (18 references in rc.5's transport, zero in
the 5.0 branch), and the UP-015 ledger that codex's own amendment created
*from this exact incident*. The gap is not theoretical: **A5-F14's release
gate requires a "bounded live F_P proof," which through Claude transport
requires the B-001 lane law the branch lost.** Under the plan's own
constitutional lineage (L0 → tapped 2.0 governs T-247), an unresolved
affected baseline item *refuses qualification* — so priority 14 hits a block
that was knowable today. Repair: add one priority row (sensibly between 3
and 4, or inside T-282's scope): establish the UP-015 reconciliation ledger
over the ten RC5 commits with per-item terminal dispositions, and route the
`worker_executes` restoration to a named code owner (T-270's transport seam
is the natural home) so F14's gate is satisfiable. My postmortem review
already recommended the amended governor assert the restored lane — that
assertion needs an owner too (T-276's assertion set).
