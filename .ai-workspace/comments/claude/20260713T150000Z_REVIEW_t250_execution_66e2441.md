## Deep review addendum (design-vs-code, added after F_H asked)

The first pass above was closure-condition verification only. The full
design-vs-code review, per the standing per-phase discipline:

**Carriers match the accepted domain model exactly.** Five-kind tagged union
with kind-specific branded refs and per-kind URI prefixes enforced at
admission; the surface row is a discriminated union where `versioned` requires
BOTH `declaredVersion` and `versionBindingRef` (no partial state
representable); binding and fact are separate carriers each with an
`authorityRef`; the internal reason union (`subject_kind_ref_incoherent`,
`surface_binding_missing/ambiguous`, `version_fact_missing/ambiguous`) maps to
EXISTING repair edit classes via a frozen table — no public schema growth.

**The judge matches the sequence and state models.** Resolution order:
binding by exact bindingRef+surfaceRef → cardinality (0 → missing, >1 →
ambiguous) → fact by identical tagged subject (kind AND subjectRef) →
cardinality → comparison only on the resolved pair. Conservation is
structural: the ticket-citation check runs for every row outside the version
branch, the seam check runs unconditionally after rows, issues accumulate
with no early return — the design's "version failure never suppresses ticket
or seam diagnostics," realized.

**All seven required differentials have named tests** (13 tests total):
mixed-subject coexistence without false drift (2 tests), same-subject drift
accumulating with ticket+seam drift, every unresolved reason mapped to its
exact repair, kind/ref incoherence unable to fabricate a binding, unversioned
ticket checks preserved under missing live facts, stale-row+stale-fact
failing without separate authority, and the release-note integrity trio —
including recognition of final versions (`4.5.1`), closing the latent t195
defect the triage found. Two tests exceed the design: closed raw admission
rejecting legacy/malformed live facts, and malformed basis input unable to
hide valid ticket or seam drift (anti-suppression).

**Small deltas all lawful:** package.json +1 is the `test:t250` script; the
design file delta is the verdict flip to accepted post-F_H; README changes
match the bindings table's role-specific language ("latest published RC" vs
"mutable source advances toward 5.0"). **Verdict unchanged: PASS — now earned
at the design-conformance level, not just the gate level.**
