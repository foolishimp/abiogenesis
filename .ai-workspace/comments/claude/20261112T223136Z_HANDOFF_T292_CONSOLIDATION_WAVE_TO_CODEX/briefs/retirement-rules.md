## Order of work

1. **Census first, committed as the Return skeleton.** Every place that names the retired thing: specification (`specification/PRODUCT.md`, `specification/requirements/**`, the other files under `specification/`), kept design notes (`T/design/*.md`; not `T/design/history`), source (`T/code/src`), scripts (`T/scripts`), tests, support and fixtures (`T/test_env`), and package metadata (`T/package.json`). For source: every declaration to delete, every caller, and every piece of kept code that imports from a file you will delete or reduce (it must keep working: say what it needs and where that stays or moves).
2. **Recorded history.** Search recorded data for the retired thing as a value: the evidence root `/Users/jim/src/apps/abiogenesis/.ai-workspace` (`*.json`, `*.jsonl`; state coverage and any size cap), `T/test_env/proof`, `T/test_env/fixtures`. Report counts. Recorded development logs that used a retired capability stop being replayable by the new build; that is accepted and you list them. **Stop** only if the retired code is needed to reopen, replay or read a store or log that the kept feature set produces (for example a default-library Run whose log carries a kind or a publication member you are removing), or if a lane that passes today on kept behaviour needs it.
3. **Specification.** Edit the Product definition and the requirements so that they state, in the present tense, the product without the retired thing. No narration of what was removed, no "retired", "withdrawn", "formerly" or version markers in live specification text; a requirement that only stated the retired thing is deleted, and identifiers of the remaining requirements do not change. If a requirement you would keep depends on the retired thing, quote it and stop on that requirement. Specification files are mirrored into the product's contracts, so these edits move the product identity; that is expected.
4. **Design.** In kept design notes, a section whose subject is the retired thing is cut verbatim to `T/design/history/<NAME>__RETIRED_SECTIONS.md` (append if it exists; otherwise create it with a first line naming the note, the commit you cut from and the line ranges) and the note keeps or gains one pointer line; a section that mixes it with live design is restated so that each sentence states what the code at head does, with the realizing file and symbol cited, and the replaced text goes verbatim to the retired file. A note whose whole subject is the retired thing moves unchanged to `T/design/history/` with `git mv`, and its line leaves `T/design/README.md`; add it to the table in `T/design/history/README.md`. Do not edit `ABI5_REALIZATION_CONSTITUTION.md` unless your brief says so; list its passages that name the retired thing.
5. **Code.** Delete compiler-first: remove a root, follow the errors, stop at kept code. No stubs, no renamed wrappers, no dead branches left behind. A shape that the product no longer admits must be **refused, not ignored**: say for each door a caller can reach what happens to a value that carries the retired shape, before and after, with the refusal code. No new refusal code or message unless your brief allows it.
6. **Tests.** A test whose subject is the retired thing goes with it (delete the case; delete the file if no case remains; delete support modules and fixtures left with no importer, naming each). A test that used it only as a vehicle keeps its claim on kept behaviour. Add one lane that shows the retired shape refused at its door. Do not weaken any assertion about kept behaviour.
7. **Generated files are not yours to commit.** After every `npm run build`, restore generated files before committing (`git checkout -- contracts product-toolchain-manifest.json test_env/fixtures/abi5-root-candidate-basis.json` and anything else tracked that the build changed; check `git status --short`). In the Return give, for the final build: the identity digests (`productContentDigest`, `contributionManifestDigest`, `publicContractCatalog.catalogDigest`, the capability graph's `graphDigest`), and a summary by file of what changed under `T/contracts` in content (rows, members, schema properties), not only in digests.
8. **Qualification mirrors.** Do not edit `T/test_env/qualification/inventory.json` or the recipe; list the members you changed or deleted.

## Stop and hand back instead of proceeding if

- the condition in step 2 holds;
- a kept requirement depends on the retired thing;
- kept code turns out to need behaviour (not just a helper) of the retired thing;
- the retirement would change what a caller of a kept Public operation observes, other than the refusal of the retired shape.
