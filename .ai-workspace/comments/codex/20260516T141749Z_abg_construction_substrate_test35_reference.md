## Source Observation

The Python `odd_sdlc` test35 line recovered useful construction behavior that
the current TypeScript ABG substrate does not yet own generically. The useful
behavior was not a product-specific outer loop by nature. It was a scheduling
and re-observation pattern over workspace/register truth:

1. observe current workspace and register state;
2. project current gaps, obligations, and residual pressure;
3. select the next lawful constructive action;
4. invoke F_P construction when content work is required;
5. admit result and execution evidence;
6. run deterministic follow-up/projection;
7. reproject pressure from admitted evidence;
8. yield, retry, re-enter, block, escalate, or close from replay truth.

The TypeScript correction is not to recreate a second product controller loop.
The correction is to make the load-bearing state and re-entry rules ABG
substrate:

- installed construction runner over admitted construction intent;
- vector-local effective runtime regimes;
- observed-state/register admission;
- overlay/frame contracts over GTL anchors and observed state;
- F_D authority placement that routes pressure rather than judging content;
- construction pressure package consumed by F_P and deterministic follow-up.

## Boundary

ABG owns the generic substrate: admission, event spine, replay, runner
selection, pressure survival, and closure routing.

Downstream products own domain graphs, domain pressure projectors, domain
evaluators, prompt rendering, and product-specific meaning.

The proof discipline is deletion-backed: every substrate primitive should
enable removal or replacement of product-local loop/controller authority in a
consumer. A substrate primitive that cannot remove downstream controller code is
speculative until proven otherwise.
