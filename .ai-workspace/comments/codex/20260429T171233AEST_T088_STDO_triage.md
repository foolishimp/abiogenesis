## Authority Walk

1. Goals:
   `GOALS.md` does not currently include `abg-total-assurance-calculus` in the active wave. T-088 remains backlog unless goals are repriced or a future active wave admits it.

2. Intent:
   `INTENT.md` already frames ABG as event-calculus runtime truth over GTL traversal, with `iterate(...) -> runtime_events` and replay-derived projection. This supports the investigation.

3. Product:
   `PRODUCT.md` currently treats one GTL edge traversal as the bounded probabilistic compute boundary. T-088 may not widen that boundary under `requirement_reprice`.

4. Requirements:
   The audit must cover the full touched runtime boundary, not only events/projection/convergence. Required candidate families include INTERPRET, BINDING, RUN, GRAPHCALL, FRAME, CONTINUATION, EVENTS, PROJECTION, CONVERGENCE, CORRECTION, LINEAGE, POLICY, PROVENANCE, RETRY, TRANSPORT, WORKER, JOB-WORKER, and GTL hook/language/vector/function surfaces.

   No design closure is allowed inside T-088. It must create follow-on design work if the audit finds a gap.

6. Code and proof:
   No tenant implementation or proof closure is allowed inside T-088. Tenant-local work must split into tenant-suffixed follow-on tickets.

## GTL Decision

The GTL question is open and major:

```text
Does GTL need an explicit assurance hook concern, or do existing
deterministic-proof and closure hook concerns already cover total assurance?
```

The target invariant is:

```text

graph-function boundary through GTL declarations, not side-door runtime config.
```

GTL should expose hook refs and opaque config. ABG resolves and enforces them.

classification, or closure folding.

identity/binding, provider/resolver behavior, or plugin contracts is a core
interface migration.

The follow-on ticket must inventory:

- projections
- reports and dashboards

No follow-on implementation may close by adding a new projection while an older
closure path remains authoritative.
