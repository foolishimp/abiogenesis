## T-149 Review

Finding 1: `deriveIterationOutcomeFromRows(...)` was an exported row-only fold
entrypoint that did not validate `GtlEvaluationScopeRef` values. The full
`deriveIterationOutcomeProjection(...)` path validated graph call, frame, graph
function, graph vector, and vector index truth, but direct callers could bypass
that validation.

Finding 2: `edgeCanClose: true` could converge an empty current satisfaction row
set through vacuous `[].every(...)`.

Fix: `deriveIterationOutcomeFromRows(...)` now accepts `basis` and
`runtimeProjection` together for scoped-row validation, fails closed if scoped
rows are supplied without that context, and requires at least one current
satisfaction row before convergence.

## T-150 Review

Finding: `admitGtlContractFulfillmentBinding(...)` rejected engine-authority
fields, but exported `constructGtlContractFulfillmentBinding(...)` did not. A
constructor caller could pass closure/event/ledger/traversal fields and receive a
frozen binding with those fields silently stripped.

Fix: the constructor now applies the same forbidden-engine-authority guard as
admission. The T-152 test proves both constructor and admission rejection.

## T-126 Implementation

The temporal runtime-scope helper was already present, but the proof was still
too shallow. It preserved output shape but did not prove fail-closed behavior
for tampered scope carriers.

Fix: T-126 now includes negative tests for contradictory temporal runtime scope
across timer-intent, deadline-breach, scheduled-continuation, and admitted event
constructors. It also validates that `TimerOutcome` belongs to the supplied
`TimerIntent` before constructing through the temporal timer-outcome event path
or scheduling continuations.
