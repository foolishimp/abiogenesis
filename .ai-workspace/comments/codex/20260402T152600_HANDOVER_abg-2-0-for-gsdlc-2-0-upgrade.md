# HANDOVER: ABG 2.0 for GSDLC 2.0 Upgrade

Date: 2026-04-02
Audience: GSDLC 2.0 upgrade agent
ABG release: `v2.0.0`
Release commit: `f8d14253a61a56935cbed57495332dd1a4378193`
Support branch: `release/2.0`

## 1. Executive Summary

ABG 2.0 exists because the prior runtime shape was semantically wrong for
`GraphFunction` recursion.

The old line could select a recursive or refined graph function by effectively
promoting inner topology into the live module/runtime surface. That broke the
foundational properties GTL/ABG needs:

- recursion was not truly local
- composition was not containment-safe
- parent truth could be certified too early
- inner alternatives could bleed into global topology
- the operative graph could drift toward macro expansion instead of lawful interpretation

ABG 2.0 fixes that by making recursion operative, invocation-local, and
containment-safe.

The short version:

> ABG 2.0 is the first release where recursive graph functions are treated as
> real runtime programs rather than as a topology-rewrite convenience.

## 2. Why the Rewrite Was Necessary

The problem was not cosmetic.
If recursive selection leaks containment, recursion is structurally invalid.

The prior shape had these failure modes:

1. Selecting a graph function could rewrite the effective live module topology.
2. Child closure could shortcut directly to parent convergence.
3. Recursive locality depended on replay/discovery patches rather than explicit
   recursive machine state.
4. Frame-local publication could degrade into synthetic fallback traversal.
5. Recursive semantics were partially declared but not fully operative.

That made the system look recursive from a distance while still behaving like a
macro/globalization system in critical paths.

ABG 2.0 corrects that model.

## 3. What ABG 2.0 Now Means

### GTL side

`recurse(...)` is no longer just decorative metadata.
The declaration now carries enough law for the runtime to interpret recursion
correctly:

- explicit termination
- explicit fold-back contract
- parent re-evaluation requirement

### ABG side

Recursive traversal now means:

- the published module remains stable
- a recursive choice opens an invocation-local frame
- frame-local publication is first-class and fail-closed
- recursive progress is carried by explicit continuation/frontier state
- child completion yields fold-back input, not direct parent certification
- the parent is rebound and re-evaluated before it can converge
- reset/reopen creates a fresh frame-attempt identity
- checkpoints are resumability aids, not a second truth surface

This is the operational meaning of “tail-loop recursive” in ABG 2.0.

## 4. Canonical ABG 2.0 Runtime Model

The accepted runtime stance is:

- stable outer module carrier
- invocation-local recursive frames
- explicit recursive continuation
- explicit child frontier
- explicit current-frame machine control
- event-sourced truth
- replay/projection as recovery and read-model support, not as the semantic
  carrier of next-action truth

ABG 2.0 should be understood as:

> a resumable recursive state machine over GTL contracts

not:

> a graph rewrite engine with some frame patches around it

## 5. Key Behavioral Guarantees GSDLC 2.0 Must Preserve

Anything downstream that integrates with ABG 2.0 must preserve these laws:

1. No global module rewrite for recursive graph-function application.
2. No synthetic traversal targets as a semantic fallback for missing publication.
3. No parent certification from “all child steps closed”.
4. No hidden fold-back semantics invented outside declared GTL recursion law.
5. No checkpoint/snapshot treated as authority over causal event truth.
6. No reuse of stale recursive attempts after reset/reopen.
7. No runtime path that bypasses frame-local containment and resolves through a
   globalized fallback instead.

If a GSDLC integration breaks any of those, it is regressing ABG 2.0.

## 6. What Changed Relative to the Old Line

These are the meaningful deltas the GSDLC 2.0 agent should internalize:

- `GraphFunction` is now a true published workflow-program surface with lawful
  recursive realization semantics.
- Recursive descent is frame-local.
- The parent contract remains the stable outer vector; inner realization does
  not become the new global topology.
- Fold-back is lawful rebind input, not parent completion.
- The interpreter owns recursive continuation/frontier truth.
- Read-only/reporting services must observe the operative graph; they must not
  secretly advance recursion.
- Install-time bootstrap is now a compressed authored read-model, not a long
  tutorial and not generated by ABG.

## 7. What GSDLC 2.0 Should Do With This

GSDLC 2.0 should upgrade against ABG 2.0 as a semantic/runtime contract change,
not as a minor version bump.

Specifically:

1. Treat ABG 2.0 as the authoritative engine/runtime contract.
2. Remove any assumptions that recursive selection materializes as global module
   rewrite.
3. Align any orchestration or planning logic to invocation-local recursive
   frames and explicit machine control.
4. Preserve read-only `gaps/status` style operations as observational over the
   operative graph.
5. Update any bootloader/install assumptions to the compressed precreated GTL
   bootstrap installed into `CLAUDE.md`.
6. Re-qualify downstream recursive use cases against containment, fold-back,
   and parent re-evaluation.
