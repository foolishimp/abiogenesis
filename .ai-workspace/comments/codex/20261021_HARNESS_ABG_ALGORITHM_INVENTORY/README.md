# Harness² and ABG 5.0: algorithm inventories and candidate loans

Derived commentary, 21 October 2026. **19 Harness groups, 23 deduplicated ABG groups and eight candidate loans.** These are scoped, source-grounded comparison lists, not exhaustive counts, feature scores, implementation instructions or new acceptance.

The scopes differ: Harness's inventory centres on optimisation/search/experiment policies; ABG's includes declared workflow composition, stock selection and execution/evidence/governance machinery. **19 versus 23 is not an apples-to-apples feature score or completeness claim.** A missing named stock policy does not establish missing expressibility.

The useful comparison is at the level of **steps, data meaning and execution binding**. Harness packages concrete search, probing, composition and experience policies. ABG already supports the composition and zoom needed to express Propose–Probe–Compose. The open question is which specific policies or mechanisms are useful under ABG's existing contracts, and whether they improve measured outcomes.

## What is most plausibly loanable

The [sparse loan analysis](transfer-analysis.md) examines width/depth search policy, comparative evidence presentation, earlier-task experience retrieval, cache/currentness checks, reproducible measurement, candidate-edit feedback, conditional choice presentation and execution adapters. Each separates semantic from realisation disposition and states its next decisive test.

ABG event admission, Event Calculus, exact recovery/continuation, proof and closure have no authoritative Harness equivalent merely because an execution produced files. Any borrowed mechanism enters below existing owners and retains those laws. No new controller/runtime, rewrite or tenant is required merely to evaluate the policy. Current 5.0 scope excludes autonomous runtime generation/recomposition/publication of arbitrary GTL and the dedicated 5.1 observer/tuner.
