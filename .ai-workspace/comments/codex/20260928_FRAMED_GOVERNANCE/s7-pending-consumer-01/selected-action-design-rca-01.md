## Root causes, not isolated repairs

### RC1 — Current-context construction was an implicit precondition

The original HOW says that a separately admitted current occurrence has current work authority and that the authority slots bind it. It does not specify the supported producer of that complete context or make the enclosing Public-start acquisition part of the covered proof.

The05 fixture spread the old environment, changed binding fields and retained the old catalog/view. Its host directly invoked lower InvocationAdmission and ExecutionBasis owners. Those owners could establish their local supplied relations without reproducing the enclosing Public start's complete acquisition. The resulting events existed but did not establish lawful supported current work. Public continuation reconstructed setup from catalog readiness and refused the policy mismatch.

The supported producer already exists: runInvocationOwner obtains setup from catalog readiness, ProductRunInvocationPort.prepare resolves installed declarations and validates input/policy/slots, and only then the owner admits the invocation, materializes/validates the graph, admits B and enters HoG. See run_invocation.ts:1239–1494 and run_invocation_operation.ts:486–581. The new current context must be the output of that composition.

**Design miss:** the continuation HOW left a materially necessary predecessor composition implicit. **Implementation/proof deviation:** the fixture used internal component entry as a substitute for that composition. **Executive miss:** the missing producer was not made a dependency of installed covered execution.

**Correction:** refine the selected HOW around one complete current acquisition and Public-start transition; consume existing owner outputs. Do not add a second context authority, duplicate every Public precondition inside lower owners, or retrofit a new catalog into an old B.

### RC2 — Occurrence identity was not expressed as a joined lookup

The original HOW distinguishes the source continuation, selectedAction and current authority slots, but says selectedAction identifies a current occurrence without specifying how repeated semantic values are resolved against the current basis. The implementation searched every historical selection with the value digest, required global uniqueness, then checked status. Current execution-basis authority was checked later.

Consequently a valid older occurrence with an equal value could make the current one unselectable even after abandonment. Selecting the first matching event also risked using the wrong event for cover timing/conservation. This is an identity/composition design omission expressed as a concrete runtime defect, not merely an extra missing negative test.

**Correction:** the current basis and semantic selection coordinate participate in the same occurrence relation. Select exactly one open occurrence within that basis; true ambiguity refuses. Cover checks use that occurrence's admission event. Admission and cold projection use the same predicate at the actual predecessor.07 implements this bounded relation; its installed integration remains unproved. No nonce, latest-wins rule or new Public field is needed.

### RC3 — Fixture composition crossed identity and carrier boundaries without their complete contracts

Three earlier failures are related but not one identical code defect:

-02 used authored catalog constants after installed publication normalization, even though the existing setup owner supplied the resolved Program to inputFactory. Both the host and the packaged nextBasis helper bypassed that output. A positional action-row assumption added another dependency on authored representation. See [02 return](selected-action-02/return.md) and [03 return](selected-action-03/return.md).
-03 placed graph-span reentry at the terminal finish slot, whose one declared result kind could not also be the converged next-action projection required for closure. The design said bounded span reentry was available but the fixture's full eight-term carrier composition had not been established. The existing selector-before-finalizer donor supplied the missing composition;04 corrected it.
-04 reused run-operation Product-set coordinates for witness admission. Those same-shaped coordinates have different owners: run authority uses Product content identity; witness admission derives full ProductInstall coordinates through the admitted capability environment. See admission_authority.ts:258–268 and run_invocation_operation.ts:364–372.

**Design miss:** the fixture realization lacked an explicit account of which owner produces each representation and how each carrier reaches its next consumer. **Reuse miss:** existing owner outputs and donors were used selectively, with copied assembly standing in for their complete contract.

**Correction:** use admitted Program input through initial and refresh computation, retain04's valid carrier topology, and derive each operation's envelope from its own existing owner/environment. Keep content identity, install identity, authored definition, admitted definition and runtime occurrence separate. Do not unify distinct coordinate meanings through a generic digest helper.

Existing Public-start support is also fragmented across scenario-specific constructors. registered-graph-selection.mjs:227 and t287-generic-job-intake.mjs:194 already contain relevant construction, but bind different scenario/entry choices.07 copied a donor into a new partial constructor. That recurrence warrants a bounded reuse decision for this successor: retain the common existing Product-owned calculations and make only genuinely different start-selection/input parameters explicit. It does not justify a new production framework or a broad helper rewrite.

### RC4 — Failure localization was treated as sufficient successor design

Returning the first failed owner predicate was useful and prevented blind installed retries. It did not establish that all dependent inputs for the next attempt were jointly constructible. Executive repeatedly authorized a local successor after locating a failure, leaving another part of the same current-context construction unestablished.

The accepted shared-causation repair is a counterexample to a blanket claim of ineffective work: it did move recurrence to its common owner and preserved the cross-Run guard. The selected-action sequence nevertheless continued to lack its complete Public current-start producer.

**Correction:** select successors from the complete bounded relation set, not just the latest error. A return must change the model of the failing composition or close it; another request/receipt is not itself a material outcome. Keep the existing first-failure stop and exact freezing, but use them to revise the whole affected construction relation.
