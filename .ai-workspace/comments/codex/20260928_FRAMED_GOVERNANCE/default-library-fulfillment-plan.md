## Selected relation

Add one opt-in fulfillment profile to the existing default-library Program and state contract:

`declared source/paired obligations/policy → actual native or C2 child evidence → independent F_P assessment by obligation → ABG identity/role/currentness/policy-completeness projection → existing parent evaluation and recursion`.

The existing Executive F_P still interprets the problem, proposes necessary work and explicitly selects a registered child. It may propose additional source-grounded obligations in that same judgment. The existing independent UAT F_P judges semantic adequacy, applicability and sufficiency under the selected frame/policy. No second semantic judgment merely restates either decision. F_D derives identities, resolves actual references, checks the declared relation and projects gaps/eligibility. A child's reported success remains insufficient.

There is no semantic-job root, stage-count precondition, new graph operator, runtime ledger, event kind, policy interpreter or controller. Fulfillment is a subordinate value projected by the already admitted default-library Result/fold/parent owners.

## Declaration and conditional applicability

An exact Program policy entry, `abg.default_library_fulfillment`, selects the library's published fulfillment-profile ref. The corresponding optional `original.fulfillment` is a closed input contract, conserved with all other original input. It contains:

- The selected profile ref and source context, `RequirementTerm[]` and **existing `GtlContractFulfillmentBinding[]`**. Initial obligation refs equal `original.requiredSupportRefs`; every declared source requirement has its pairing or an explicit null-policy/contract gap.
- Existing `SemanticProofPolicy` and `SemanticProofShape` rows selected by those binding refs. Reuse their source bindings, role-contract refs, required evidence roles, scope, required content and unproved scope. These subordinate rows are input policy, not new catalog entries.
- A closed policy-completeness selection for each proof policy: semantic criterion refs, depth-class refs and their applicability criteria, allowed discovery classes/templates, and the named bounded strength rule below. Empty optional classes mean none selected; a missing required class is a gap. No adapter invents deeper or stronger requirements.
- The exact installed consumer assessment contract ref and its declared fulfillment response field. It must agree with `original.assessment.resultContract` and the existing installed schema asset. It declares the structured assessment below; a generic satisfied string cannot stand in for it.

Applicability is established from the already bound Program policy and known default-library owner before interpreting the optional input or response. A selected profile with missing/malformed declaration, mismatched contract or unknown owner refuses before an actor or child. A structurally valid declared null support is an open gap, not malformed input. With no selected profile, existing S5 semantics apply; unrelated payload fields never activate fulfillment. Supplying `original.fulfillment` to the default-library family without its matching Program selection refuses rather than silently dropping an asserted contract. Other families retain their own payload interpretation.

Validate source spans against exact original source bytes at acquisition, using the existing observed context and member digests. Resolve contract refs through the existing unique installed contract owner, including imported ownership; do not copy contracts into the consumer. Once admitted, internal calls consume that bound immutable declaration. They do not rehash the whole Program, graph, declaration or input on every handoff.

## Raw judgments, derived identities and conserved state

For the selected profile only, extend the existing synthesis raw contract with `requirementProposals`. A proposal contains a local candidate ref, source quotes, semantic meaning/reason, an allowed policy/shape template ref or explicit missing-policy gap, predecessor requirement refs where applicable, and actual supporting Result refs. It cannot emit coverage, an admitted obligation ref, removal of an original requirement, parent completion or authority expansion.

At the existing admitted synthesis → choice projection, ground the quotes and derive task-scoped requirement/obligation identities using the existing source-binding and fulfillment-binding conventions. Repeating the same proposal conserves its identity; a conflicting reuse of an identity refuses. New obligations are added to the active set; refinement does not silently retire earlier obligations. Policy/shape instances remain constrained by the original declared templates. A new obligation without usable policy stays open. This source-grounded meaning remains attributed to the actual synthesis F_P Result; its structural admission is not an independent semantic certification.

`GovernanceWorkState` gains one optional current fulfillment projection: active initial/additional bindings with their introducing Result refs, and per-obligation evidence/assessment refs, disposition and typed gaps. Original terms/policies remain in `original`; additions carry only their newly derived rows and provenance. No nested prior full Result or input is stored. This is an ordinary projected Result value, with no independently writable store, append API, event lifecycle or second decision history.

The existing selected-profile state invariant changes from “all original support refs while open” to “exact unresolved active obligation refs.” Original bindings and admitted additions must survive choice, child input, retained foldback, recursion and parent reevaluation. Only ABG's projection changes coverage/residual rows. Native reports and raw assessment candidates cannot supply an obligation delta. Non-profile state validation remains unchanged.

## Evidence and independent assessment

Extend the existing UAT consumer schema with a closed fulfillment assessment. Each active obligation has exactly one judgment: `satisfied`, `falsified` or `indeterminate`, with reason, selected policy/shape refs and typed support selections. Support names an actual admitted Result ref plus its role and, when relevant, observed artifact path/digest or command/predicate id. The response also judges every selected semantic criterion and depth class, records justified non-applicability or gaps, and reports completeness of each selected discovery class. Raw bytes remain intact; missing, duplicated or foreign references refuse, while valid negative/unknown judgments admit and leave the parent open.

The schema carries current obligation, policy, shape and evidence domains. Instructions explain those same relational rules and the original outcome; they do not contain a desired verdict. The actor sees actual artifact content, full selected source, prior assets and admitted observations needed for its judgments. Preserve the existing separate read-only assessment actor, selected frame assembly, exact producer and current candidate/rubric identities.

| Role | Actual source and check |
|---|---|
| Realization | A file entry in an admitted native-work after-context, or an admitted observed-input C2 protected snapshot. Supplied work has observation provenance, never invented authorship. The F_P support selection names its meaning; F_D verifies exact path/digest and applicable contract. |
| Verifier artifact | Exact selected verifier bytes in the admitted C2 snapshot/native observation, separately identified from the realization. Filename, purpose label and file presence do not assign this role automatically. |
| Verifier execution | Actual admitted C2 command/predicate observations, their input/snapshot identity and current selected command configuration. A native report that commands passed is not this role. Nonzero exits remain truthful observations. |
| Semantic assessment | The current admitted independent native assessment Result and its exact consumer contract. Its per-obligation judgments provide semantic attribution; the enclosing generic native-work observation remains the actual outer Result contract. |

For contract matching, distinguish the outer native/C2 Result contract from the inner consumer assessment contract. `GtlContractFulfillmentBinding`'s realization/proof refs must resolve to actual output contracts; the policy identifies which evidence role supplies that side of the pair. The inner assessment schema is checked through `NativeWorkspaceAssessmentSelection`, not falsely treated as the outer CCall contract. An expected role with no supported source is a gap. No purpose-label restriction on the native producer is introduced.

Preparation supplies the actual closed child Result/CCall/actor coordinates already established by foldback. Extend/extract the current `result`/`subjectEvidence` helpers to resolve explicitly named refs via the existing event index and exact invocation/basis relation. The already computed `inputOrigin.retainedProjection.sourceResult` remains the source at fold. Do not reconstruct C2 CCall identity from `source.provenance.cCallRef`, which C2 omits.

Derive the compact artifact/command support facts while consuming that admitted child at the existing fold; do not re-admit its immutable producer at every later hop. UAT preparation compares selected artifact support with its current observed context; execution support must reference the same protected bytes/configuration. Changed relevant bytes invalidate dependent support; unrelated support and its original evidence refs survive. Existing post-assessment invalidation protects parent closure. Replay uses admitted contexts/snapshots and causal identities, not current filesystem or ambient environment.

## Completeness, discovery and parent closure

The new pure `projectGovernanceFulfillment` consumes the selected declaration, conserved active bindings, trusted support facts and the actual independent assessment. It produces per-obligation coverage and residual rows plus eligibility for this declared claim. It checks total relations only:

1. Every active binding has its exact requirement, source, contract, policy and shape; no original or newly admitted obligation disappears.
2. Every required evidence role is supplied by an admitted compatible source with exact dependency identity, invocation/workspace scope and currentness. Required realization/proof sides stay distinct even when one observation contains several artifacts.
3. The independent F_P has supplied a satisfied judgment for every selected semantic criterion and applicable depth class, or an explicitly justified non-applicability judgment where the policy permits it. F_D checks domains, attribution and support; the justification's meaning remains the F_P judgment.
4. The selected strength rule is mechanically satisfied over those admitted facts. The first supported named rule is **declared roles plus current evidence and independent assessment**: each declared required role exists, dependencies match, the assessor is independent of the selected author/producer, and any explicitly required adverse-case evidence meets its declared command-exit or existing C2 predicate disposition. A ref labelled “counterexample” is insufficient. This is a bounded F_D strength admission, not a model-emitted strength label or a claim of universal assurance. Policies needing a different unsupported rule produce a typed policy gap, not a guessed implementation.
5. Every selected discovery class is accounted for. The first supported source is the explicitly typed requirement-proposal collection: all admitted proposals create conserved rows; the independent assessment judges whether those proposals cover the declared artifact-dependent class. A reported missing member creates an open discovery gap and returns that pressure to the next ordinary Executive judgment. A policy requiring automatic enumeration from a different structured artifact needs its declared typed relation; unsupported enumeration stays open. Startup cardinality never caps later admitted proposals.

The schema distinction is deliberate: existing `SemanticProofPolicy` prose and `SemanticProofShape.requiredContent` do not express typed depth applicability, discovery completeness, evidence-role selections or strength admission. The subordinate completeness selection and structured assessment above are the minimal new fields. They do not parse those strings into executable rules. F_P assesses semantic sufficiency; the named F_D relation checks completeness of the explicitly selected policy against admitted refs.

`projectGovernanceParent` consumes this projection on the opted-in Program. Closure requires its existing current independent UAT relation **and** eligible coverage, policy/depth completeness, the selected strength relation and no unresolved active obligation/gap. A satisfied scalar with missing evidence remains open. Valid falsification/indeterminacy remains an admitted Result and returns through the existing recurse application; malformed provenance refuses. No requirement is closed by child return or the Executive's work selection.

When physical work changes a dependency, the existing fold exposes that observation and makes affected coverage stale before the next parent evaluation. A new assessment can support current bytes; old evidence is retained historically and receives no credit for a different subject. Original task/support, unaffected bindings and prior evidence identities remain conserved through the same admitted recursion. No new continuation owner is required.
