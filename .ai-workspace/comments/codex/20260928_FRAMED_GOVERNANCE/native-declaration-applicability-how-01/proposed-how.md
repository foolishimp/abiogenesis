## 3. Complete proposed existing-owner HOW

NCC-F02 consumes the same finite selected Product set, each Product's actual

### 3.1 Preserve metadata integrity independently of declaration selection

Factor the existing metadata-body admission inside `declaration_exports.ts`
so both branches consume one result. It is private pure factoring of the
current owner, not a new API or independently authored validator.

For every current verified Product, preserve every metadata member, exact text
and digest. Require the producer's identity-matched evidence envelope, real
arrays, contained normalized unique Product-relative `package.json` paths,
fatal UTF-8 decoding, JSON object bodies, valid explicit module-format values,
and exact source-text SHA256 agreement. Preserve the current root metadata
name, nonblank version and module-type checks. The actual root package version
continues to match the manifest/artifact through the existing producer's
verification; do not add a second package-version field to `NativeLinkProduct`.

Retain the existing lexical consistency checks for root bundle declarations:
valid unique package names, agreement when both bundle field spellings are
present, valid dependency-name/version entries, and declared bundle membership
in root dependencies. These checks inspect declarations; they do not require
or select any dependency package path. Once a native Product selects the
finite declaration profile, its existing selected-package identity, dependency
and optional-dependency checks still apply without alteration.

A current verifier-produced artifact contains its root record and every
inventoried `package.json`. The new empty-domain branch must not manufacture a
root, drop records, accept omitted current producer metadata, coerce malformed
arrays to empty, or substitute another Product's evidence. Completeness comes
from exact artifact verification and the same owned invocation/context; the
linker does not invent a second payload inventory or independently rescan the
host. Removing/replacing admitted metadata is an evidence substitution, not
an applicability decision.

The existing metadata-absent native helper/request domain retains the already
accepted self/platform/no-proven-bundle behavior used by native source fixtures.
`NativeDeclarationClosureRequest.packageMetadataSources` explicitly says
absence proves no bundled ownership. That existing helper relation grants no
omission of the current verifier's actual Product metadata and does not create
an empty verified-Product witness. No synthetic metadata is introduced to make
those native fixtures pass.

### 3.2 Admit empty native applicability only from congruent actual evidence

For Product P, let A(P) be its actual parsed public-contract rows carrying a
`nativeTypedLocator`, and E(P) the same Product's verifier-owned evidence.
The linker checks actual arrays and identity before reading their cardinality.
The complete empty relation is:

```
EmptyNative(P) iff
  E(P) has the same Product/content/package coordinates as P
  and E(P) is the valid actual producer evidence envelope
  and actual advertised native rows A(P) = []
  and E(P).sources = []
  and E(P).closures = []
  and E(P).contracts = []
  and current producer metadata/root evidence passes 3.1
```

Array-like objects, null/missing arrays, a missing or contradictory evidence
identity, malformed metadata, and unproven absence do not satisfy this
predicate. Zero advertised rows with any nonempty declaration source, closure,
contract or associated selector is contradictory evidence and returns the
existing `incompatible_dependency` refusal. An advertised native row with an
empty or incomplete native evidence set also refuses; it must not enter the
empty branch merely because three arrays were substituted.

Before linking native participants, retain exact advertised/evidence contract
correspondence: each advertised native contract has one matching evidence
contract with the same ID/digest/export/named symbol and its admitted closure;
no surplus evidence contract creates authority. The existing producer performs
full evidence derivation, and the existing linked checker still validates its
actual symbol and source inventory. This checks the join and prevents an empty
helper return from erasing an advertised contract. It does not introduce a
second parser for native meaning or alter permitted same-symbol serialized
contract rows.

An accepted EmptyNative(P) contributes no checker declaration root, no symbol
admission, pending selector, semantic occurrence or external binding. Its
metadata is retained and validated as exact payload evidence, but is not
injected into the linked declaration source host and does not cause bundle
closure or declaration-target selection. Its runtime JavaScript supplies only
its already declared ordinary public guard function when later consumed.

P remains in the selected Product set, direct dependency graph, compatibility
and required-contract/capability validation, identity checks and lock rows.
Its original Product-set position and virtual-root coordinates are retained;
do not filter or renumber the inputs. A required native external target cannot
be satisfied by EmptyNative(P): the target has no admitted native root/symbol/
contract, so the existing direct-target and exact binding relation refuses.
An asset-only Product dependency remains subject to its existing dependency
law, without gaining or losing native authority.
