## DL-D01 — C2 observed input cannot run as the proposed Testing child

Proposal references: `default-library-plan.md:41,64–72,100–110`.

The Testing row says to reuse C2's native-source **or observed-input** arm, and
the execution relation calls the selected wrapper and its fixed child inside
one admitted traversal. Consider an ordinary supported input containing an
already-valid candidate and check plan, with current file observations but no
admitted native-work producer. Selecting Testing should execute those checks
without rerunning an author. Constructing an
`ObservedWorksiteCommandExecutionTask` succeeds structurally, but the existing
runtime cannot admit or execute it as this child:

- `code/src/abg/execution_basis.ts:714–724` binds the observed-input arm to the
  exact **root** C2 Program, graph and raw invocation input.
- Child admission at `code/src/abg/execution_basis.ts:2411–2417` requires
  `deriveSameRunWorksiteCommandSourceBasisAtPrefix`. Its non-native branch
  reaches `code/src/abg/worksite_input_provenance.ts:305–309`, which explicitly
  excludes observed-input tasks. The child therefore receives
  `child_input_mismatch` before its commands run.
- The pre-effect owner independently refuses every observed-input child at
  `code/src/abg/execution_basis.ts:980–981`. Replay also expects a completed
  source Result through the same derivation at `code/src/abg/replay.ts:1789–1798`.

All `code/` references here are relative to
`build_tenants/abiogenesis/typescript/`. These are direct source relations,
not a newly executed failure. The trigger is deterministic for the proposed
observed-input child. Current controls fail closed; no unauthorized command or
false success was observed. The practical harm is a blocked Testing capability
on reusable input, or pressure to insert an unnecessary native author call.

**Smallest correction:** state the two C2 source cases explicitly in HOW. Keep
the existing same-Run native-source path unchanged. For observed-input children,
name the exact admitted parent/preparation observation → selected files/task →
child binding and currentness relation, using the existing child-admission,
pre-effect and replay owners. An observation of existing files must not acquire
a fabricated author/source Result. Merely adding the proposed library
preparation/result arm in HoG and `c_call_outcome.ts` does not supply this
relation. If Executive selects only the fresh native-source thread initially,
mark observed-input child support as an explicit remaining gap; do not claim
that branch delivered. Neither remedy needs another planner, event family or
mandatory construction step.

## Bounded conclusions on the proposed owner additions

The ordered semantic-job adapters are genuinely unsuitable for the new
conditional library: `product/semantic_job.ts:865–873` requires its selected
stage/predecessor position, and `abg/semantic_job.ts:471–500` consumes that
envelope. Their restriction does not extend to the underlying native owners.

A narrow delivery of the **existing** occurrence basis to the new preparation
and fold leaves is justified. Generic leaf occurrences do not expose the
admitted workspace environment or event prefix; HoG currently constructs this
basis only for its selected native families
(`hog/ccall_lifecycle.ts:456–477`).
`abg/execution_basis.ts:158–240` already supplies the needed input, Program,
environment and producer-prefix access for F_D as well as F_P. Preserve its
constructed object and private derivation as the proposal requires. Additional
full-definition/history authentication is not justified.

Most other joins already exist and should remain their owners' work:

- Pure native-task construction, actual context observation and fixed native
  execution/assessment remain in `product/native_workspace_work.ts:23–52`,
  `product/worksite_operations.ts:1076–1088` and
  `implementation/native_workspace_work.ts:25–66`.
- Generic retained-input edges already bind the actual parent entry, selected
  completed child and returned value
  (`abg/traversal_route.ts:4075–4108`,
  `abg/worksite_input_provenance.ts:237–301`). Native producer Result/CCall
  projection already exists in
  `abg/native_worksite_execution.ts:41–91`. The library does not need another
  foldback or producer ledger.
- Library state conservation and policy selection remain declared application
  contracts/pure projections. A narrowly selected admission arm may check their
  output against these existing owned facts; it must not make induction,
  design, test counts or residual interpretation into generic ABG admission law.
- Independent assessment requires the existing concrete source/candidate/rubric
  file digests, real producer coordinates and installed result schema
  (`product/native_workspace_assessment.ts:15–31,63–70`). Its schema contract
  must also be declared by a Program-member graph, and the fixed assessor must
  have the selected run-environment role
  (`abg/instruction_assembly.ts:117–135`). The proposed module/contracts and
  preparation boundary can supply those joins without renaming the native
  leaf or adding a new assessment engine.

Apart from DL-D01, no blocking contradiction was found in conditional catalogue
coverage, source/residual conservation, F_P judgment versus F_D projection,
independent assessment, parent closure or consumer-owned Hello acceptance.
The proposal preserves the relevant donor policy meaning while excluding the
fixed lifecycle route. Its one installed proof thread remains a prospective
discriminator, not seven-capability qualification or general model reliability.

This review inspected only the proposal and material producer/consumer seams.
No source changes, tests, build, install, provider call or Git operation were
performed. It does not claim that the unimplemented library satisfies Product.
