## Input, Selection And Output

The pure constructor accepts `(T, K, Q, V, F)` through one ordinary consumer
input contract. It retains source/task identities and the original completion
predicate; exact owning requirement, obligation, policy and binding refs;
observations and evidence selections; explicit interpretation/fit judgments
and owner rulings; and available published GraphFunction declarations.
The caller cannot establish satisfaction or coverage with booleans.

`M` and `R` are disposable views of those owning relations. They are neither
new authoritative requirement carriers nor a writable evidence/closure ledger.
The first implementation processes finite prerequisite relations among
construction, execution and evaluation duties and their declared applicability.
It preserves owning conjunctions, alternatives and qualifications; an
unsupported relation remains a gap rather than being flattened to a checklist.
Open prose, incomplete interpretation or an unclassified clause prevents a
full-task completion claim. A source-linked judgment warrants semantic coverage;
schema checks and hashes cannot provide it.

Selection is a bounded traversal of the supplied duty/dependency population
and available function contracts. It chooses a dependency-ready increment `U`
under the explicit policy and carries the remaining owning refs. A missing
prerequisite can be selected as work. Cyclic/ambiguous bindings or a missing
compatible function return the affected gap; there is no synthesis/retry loop.
Applicability true includes the duty, false excludes it with its basis, and
unknown preserves the dependent uncertainty. An omitted mandatory evaluation
cannot be hidden by a caller's preferred-frame list.

| Established basis | Required candidate work |
|---|---|
| Artifact absent | Native construction, execution and required evaluation. |
| Valid native artifact; execution absent | Native reacquisition, execution and required evaluation. |
| Valid artifact/execution; required evaluation absent | Reacquisition/currentness and that evaluation only. |
| Negative, indeterminate or incomplete evaluation | Preserve its verdict and scope; select warranted repair/investigation/missing evaluation or return a gap. |
| Every obligation established | Report the existing admitted support refs. |
| Stale/unknown support | Withdraw affected reuse, preserve unaffected support and carry the residual or select authorized discovery. |

An evaluation may be a published total `F_D` computation, a distinct `F_P`
semantic judgment or an owner decision according to its actual duty. Code does
not convert meaning or reserved authority into deterministic truth. Independent
assessment must bind the exact source, execution, required scope and satisfactory
verdict, with distinct required producer identities. Its existence alone is
insufficient. Missing historical construction inputs remain a separate duty.

The output is ordinary candidate GTL, entry data, an obligation-to-producer/
reuse/evaluation correspondence and carried refs/gaps. Author-time selection
over supplied evidence remains provisional until the existing owners
authenticate that evidence. `established` is reported only from authenticated,
applicable support covering the original predicate. A report is not a new
closure fact. A successful selected increment does not close the original task.

## Ordinary Function And Binding Relation

The first library uses existing native work, native assessment, command
execution and native reacquisition GraphFunctions, plus a supplied published
evaluator where its contract fits. Each selection binds the function's exact
publication/name/digest, input/output contracts, preconditions, effects, context
needs and evidence duties. A semantic-fit judgment is required where these do
not have a total declared rule. Name, type or tag equality alone is insufficient.

Pure parameterized factories already produce concrete `inline_graph`

## Publication Before Admission

1. Resolve explicit source-linked facts, current owner observations and the
   available published contracts; produce a candidate and unresolved refs.
2. Emit concrete ordinary GTL and packaged implementation/schema declarations
   through the existing GLC Product emitter. No future Run result is a
   prerequisite for authoring this candidate.
3. Validate/freeze/package the successor under ordinary Product ownership;
   install and admit its exact publication, catalog, implementations and schema
   assets. No mutable source import stands in for an installed Product.
4. Construct the current workspace binding/grants and ordinary entry data;
   select `historicalSource`, exact source-child proof and run environment as
   resources. The generated Program then enters ordinary `run.invoke`/start.
5. ABG authenticates at the declared acquisition/judgment boundaries; HoG
   traverses only the generated GTL; existing owners perform effects and admit
   results. Public result/readback supplies evidence of the actual path.

This sequence avoids circular admission: publication identity has no future
workspace grant or authenticated-result dependency. A changed topology receives
ordinary new declaration identity and admission; a bound running Program is not
rewritten. Subsequent increments require their existing entry/re-entry authority.
There is no automatic cross-Run controller.
