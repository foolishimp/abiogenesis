## 2. Truthful handoffs, with explicit owner obligations

The common comparison takes `JsonValue`; changing that signature while adding `as JsonValue` at its callers does not satisfy C2. A shallow guard must never turn a `RuntimeEventBodyView` into a JSON value. Conversely, inserting I-JSON admission before every comparison would change existing semantics: the current common test intentionally retains sparse-array behavior and unsafe integral numbers. Neither blanket change is proposed.

For already admitted data, retain the actual value and expose its truthful type from the producing owner. Plain data declarations may use complete structural type aliases that are assignable to `JsonValue`; every property must remain represented and checked. Do not intersect an unproved type with `JsonValue`, omit extra fields to make a projection compile, introduce a generic assertion wrapper, or replace a handle with its enumerable fields. Existing raw/schema admission should pass its checked **output** forward rather than discard that evidence and reassert the raw candidate at each handoff. This is type/data plumbing at the existing owner, not a new canonicalization algorithm.

## 3. One synchronous record framer

Add to `shared/canonical_json.ts` a single framing callable:

```ts
type CanonicalJsonSink = (part: string) => void;
function writeCanonicalRecord<T>(
  acquire: () => readonly (readonly [string, T])[],
  writeMember: (member: T, key: string, sink: CanonicalJsonSink) => void,
  sink: CanonicalJsonSink,
): void;
```

Contract: write `{`; call `acquire` once; sort a private shallow copy of the entries by primitive string keys using the canonical code-unit order; for each entry write its comma if needed, encoded key and colon, then call its member writer exactly once; write `}`. The owner supplies one entry per actual own enumerable string key. The helper neither reads an owner value nor interprets a member token. It propagates the original acquisition/member/sink exception immediately, with the exact emitted prefix and no later callback. It does not materialize an iterable, cache a value, catch an error or authenticate a prefix.

The ordinary `writeCanonicalJson` object branch acquires `Object.entries(value)` **before** calling the framer; its callback recursively writes the captured value. This preserves the current eager value-getter phase before any output. Sorting already captured primitive keys has no supported property-acquisition effect.

The three selected streaming owners acquire `Object.keys(body)` in the `acquire` callback, **after** the successful opening brace, and use each key itself as the token. Their member callback reads the body only after the successful key/colon writes. Preserve these owner dispatches:

- `c_call.pendingInteractionBodyDigest`: the validated-plan branch writes its current stored member; the owned-plan branch uses `writeRuntimeEventPrefixValue` / `writeRuntimeReplayGuardValue`. Keep `pendingInteractionPlanBody` and nominal plan checks.
- `retry.completedRetryProgressPlanDigest`: keep the owned prefix and replay guard writers; only other members use ordinary canonical JSON.
- `replay.writeReplayBody`: lookup `selected?.[key]` after the colon. If present, write `[`, call that factory once, and consume its iterable once in order; otherwise read/write `body[key]`. Unselected factories are never invoked. `digestReplayBody` remains the hash-sink adapter delegating to `writeReplayBody`.

The private framing loops disappear. Owner hash creation, prefix/replay authentication, preimages and lazy member dispatch remain. One ordinary writer and three streamed writers now compose the same framing algorithm, with explicit acquisition timing rather than syntax-only merging.
