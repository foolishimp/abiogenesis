# Prepared deterministic observation protocol

The original frozen runner remains the uninstrumented endpoint witness. Baseline P1 and repaired-support P3 are closed successful endpoints. Final candidate P1/P3 must use that runner and oracle on the final archive. Failed baseline P3 setup and candidate01 are separately identified historical subjects. No endpoint or diagnostic workload ran in this preparation.

After each selected endpoint succeeds, a separate Executive grant may activate one same-subject P1 or P3 repetition on fresh canonical external roots. `diagnostic-runner.mjs` authenticates the original configuration/grant, script/toolchain/subject pins and endpoint result, then runs the unchanged original runner under `/usr/bin/time -l` with explicit trace flags and a hash-bound preload URL. Its original no-NODE_OPTIONS preflight is retained. There are no PATH shims, provider calls, retries or cleanup. An explicitly enumerated npm edge runs the exact pinned npm CLI script through the exact pinned Node with the same application arguments; this diagnostic launch difference is recorded. Unlisted external children are disclosed, not silently instrumented.

`diagnostic-preload.mjs` separately authenticates itself in each Node process. It binds loaded canonical file URLs to declared stage/installed roots and exact emitted SHA-256 before appending diagnostic attachment calls. The original module body is unchanged; both on-disk and loader bytes are checked. Stage and installed copies are different module identities even when bytes match. The final configuration must pin the final emitted history, prefix and canonical modules, plus their exact baseline equivalents in the baseline configuration. No moving or original candidate01 module is substituted for final emission.

The synchronous observers call each original once with its original receiver/arguments and return its result or original thrown object. Crypto input bytes, JSON returned text, canonical sink parts and successful UTF-8 writeFileSync input bytes are separate channels. The canonical observer counts parts delivered through the original sink, not a new encoding or second traversal. Promises are never wrapped or given extra rejection handlers. RuntimeHistory samples its actual existing cumulative `work` fields after calls; selection extents, new scope rows and actual RuntimeEventIndex pre/post advance fields have separate meanings. No event/body/selection object is retained by the observer. Unknown quantities do not become zero.

Node native filesystem trace records explicit completion byte results. Sync UTF-8 fast paths omit that field; `unsized` counts those completions rather than estimating bytes from decoded strings or stat sizes. Failed negative results are counted separately, never added as bytes. `fs.writeFileSync` successful UTF-8 bytes are an API channel and can overlap native trace; do not sum them. Trace includes preflight, evidence and observer IO, while JS counters suppress the observer's own hashing/serialization. The final one-record observer write and trace files are separately inventoried overhead. No byte counter is an OS-wide disk, allocation or unique-data total. This selection follows the exact [Node 24.7 filesystem implementation](https://github.com/nodejs/node/blob/v24.7.0/src/node_file.cc).

The loader uses [Node 24.7 synchronous customization hooks](https://nodejs.org/download/release/v24.7.0/docs/api/module.html#synchronous-hooks-accepted-by-moduleregisterhooks), and synchronizes changed builtin exports through [syncBuiltinESMExports](https://nodejs.org/download/release/v24.7.0/docs/api/module.html#modulesyncbuiltinesmexports). Hooks and globals exist only in the separately configured diagnostic processes. Worker threads are not an assumed observed population; unexpected edges must be disclosed and triaged.

Every observed Node PID records wall interval, CPU microseconds, `resourceUsage.maxRSS` in KiB and memory samples. These begin after preload authentication and end in its exit handler; later exit handlers are outside the JS snapshot. Wrapper elapsed time includes launch/preload. Original runner interval records remain their original scopes. Parent CPU is not child CPU, samples are not heap peaks, and maxima are never summed. Raw macOS `/usr/bin/time -l` provides its own complete-command scope and units. Non-Node descendants lack these per-PID counters and remain explicit. Capture exit status/signal and all stdout/stderr before interpretation.

After closure, retain exact archive/member bytes, original workload outputs, event-log bytes and process traces. Inventory each host/install/worksite/scratch/source-mirror/evidence/diagnostic root by regular files, logical bytes, links and `/usr/bin/du -sk` KiB. Record overlaps and copy-on-write caveats. Measure final evidence after its own last receipt; keep trace/preloader/preparation cost visible. Compare diagnostic overhead only to the matching uninstrumented subject/lane, without treating the difference as a clean causal subtraction or statistical estimate. No speed threshold or new heap quota is selected.

`output-correspondence.json` preserves the already selected producer-bound relation: literal outputs and logical owner contracts exact; archive, fixture, install, event and physical identities retained and related through their actual producers. Never normalize away refs/digests/currentness. The original oracle and fresh-read conservation must pass before a diagnostic observation can support cost interpretation. A diagnostic pass is not semantic acceptance. Missing fast-path read bytes, internal cold-scope causal iteration counts, cache memory and external-process measurements remain unobserved unless separately closed. P4 is one capability witness and is never repeated for measurements.
