## R-L2-001 correction assessment

The actual delta is limited to successor status, the E03 territory description
and the new timer-domain subsection. No Product, schema, duration admission,
dependency, historical evidence or production implementation changed.

The design now requires one common internal timing mechanic within the
already selected physical-lifetime module. It preserves positive safe-integer
owner durations and the native wakeup's positive finite-number domain. Host
timer arms stay within the host limit; monotonic elapsed/remaining time is
rechecked before consequential action. Representation and rounding must not
overflow, truncate the declared wait or make a remaining wait eligible early.
This directly excludes the clamped raw-timer counterexample.

The selected causal cone includes grace, confirmation and drain, worker lease,
absolute and native-wakeup delays, and the command timeout. Owner policy still
determines renewal and consequence. Already bounded HTTP socket, heartbeat and
polling mechanisms retain their distinct role. No Product-domain narrowing or
broader timer framework is introduced.

Cancellation invalidates pending callbacks; rescheduling replaces the prior
generation; lease renewal cannot reset the absolute limit. Due active actions
and lifetime completion occur once, cancellation prevents the action, first
failure survives, and strengthened cleanup cannot extend the existing final
bound. These constraints conserve the owner/effect relation rather than
merely swapping timer APIs.

The finite oracle now covers host maximum minus one, maximum, maximum plus
one, large admitted finite values, fractional wakeup, premature callback,
early/between-chunk cancellation, stale reschedule callbacks, absolute-limit
independence and strengthened cleanup during grace/confirmation. Controlled
clock evidence is explicitly local and cannot replace the required actual
process, installed-owner or native-consumer evidence. No days-long execution
or new test framework is required.
