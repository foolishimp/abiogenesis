Graph `edge/compose/substitute/recurse/fan_out/fan_in/gate/promote/identity/same_object` and the eight traversal continuation alternatives must each have a disposition for the selected release and each supported C application. Do not generate every possible graph walk. Use closed constructor cases, documented guard partitions, recursive induction obligations and dependency-selected compositions. F_H language declarations and lawful hold/refusal are distinct from the 5.1-native response/resume qualification allocation.

Owner result unions remain domain values. A method result is indexed by a declared predicate, subject and basis. For example, an actual failing test can satisfy “the declared measurement executed and was admitted” and falsify “the application meets the tested requirement”; these are two different evaluations, not one tag with two core meanings. A successful physical install followed by refused ABG admission satisfies neither “installed runtime fact admitted” nor “whole preparation completed.” If the exact basis is missing, that assessment is `invalid_basis`; if admissible evidence cannot determine an applicable property, it is `indeterminate`. `out_of_frame` identifies a capability/scope mismatch. `not_performed` is absence of evaluation, not a new core value.

The binding should give each declared operation/outcome one interpretation under its exact predicate and preserve the cause. It should not globally map `result`, `blocked`, exit code 0, `F_D`, `F_P`, `F_H` or an Event kind directly to a method core value.

There is a further vocabulary hazard: [AXIOMATIC_CALCULUS §5](stdo://releases/v3.0.0-rc.1/standards/AXIOMATIC_CALCULUS.md#5-traversals-and-functor-kinds) says its traversal/functor-kind terms do not import other owners' same-spelled terms. Its `F_D` classification denotes deterministic evaluation/proof, while ABG's deterministic leaf regime also executes domain construction/effects. The explicit interpretation must classify operation kind and authority; it cannot identify every ABG `F_D` execution with an a_c evaluation or declare every human-executed operation `F_H`.

### Refinement, effects and state laws

For the cleanup, the important conserved relations are:

1. `admittedOutput(producer)` supplies the consumer's current input through the declared transfer; graph-entry input remains a separate immutable coordinate.
2. `fold(L ++ suffix) = foldStep(fold(L), suffix)` at the same exact declarations and committed boundary, for the declared projection. Equality of final values does not by itself establish absence of repeated work or correct intermediate admission.
3. Cold reconstruction and live current-state projection agree at the same cut; neither proves current physical workspace truth without the required observation.
4. Reuse requires admission, dependency validity and applicability. Ordinary function boundaries do not invalidate immutable established facts; a changed grant, definition, observation or consumed input does.
5. `decode(encode(event)) = event` only for the codec's declared admitted domain and its authentic earlier inline source. Logical identities and actual encoded byte coordinates remain distinct.
6. An event append publishes no tentative source, index, profile, hash or current state before its actual complete durability boundary. Failed rollback poisons physical ownership rather than fabricating a clean successor.
7. An admitted failure, absent Result or lost process is not proof that no effect occurred. Continue, retry and fresh-work reuse have different predicates and do not share an implicit “resume” default.
8. Valid retained producer work survives consumer preparation failure with its original actor/result/judgment identity. A new Run does not copy old events or impersonate the old Run.
9. Exact completion consumes all applicable return, evaluation, closure and evidence obligations. No child result, response parse, complete prompt, component test or fixture success closes an enclosing claim.

Existing owners supply these laws. Their compact derivation should link back to Product execution/context law, EVENTS, CONTINUATION, selected runtime HOW and the three realization views, not restate them as new method authority.

## Concrete reconciliation findings and discriminators

### C1 — Active direct-GTL design still projects catalog runtime authority

Current [Product definition/tool/runtime table](../../../specification/PRODUCT.md#definition-tool-and-runtime-authority) states that Catalog/view/declaration application are pure and eventless. However [M03 direct traversal design](../../../build_tenants/abiogenesis/typescript/design/M03_DIRECT_GTL_TRAVERSAL_BEHAVIOR_DESIGN.md) still assigns `AdmittedCatalog` and CatalogView to ABG admission (117–118), names ABG catalog admission in the authority table (282), says `admitCatalog` emits a catalog event (308), and shows that message in its sequence (1041). Other lifecycle/domain rows carry those old classifications.

Counterexample: a worker reconstructing only the current accepted direct-GTL views could implement a Catalog event or lifecycle, which Product expressly prohibits. This is an existing stale projection; current higher authority decides the answer. Repair the complete affected ontology/authority/domain/sequence/state/atomic-function projection cone, reusing current Product-ready catalog semantics. No new Product outcome or runtime redesign is required. Do not alter historical acceptance hashes.

### C2 — The affected computational binding is distributed, with source-only changes ahead of one joined proof

The strongest existing algorithmic and ownership rules are already present, but their joined current boundary requires reconstruction across the constitution, multiple HOWs, cleanup returns and the source. That does not establish UP-018 sufficiency for a new worker.

Discriminator: give a worker only the selected method and accepted binding/design, and ask where a scope-index cache may be reused after a changed current authority and after close/reopen; which consumed facts must be reacquired; and whether private validation candidates can act as admitted history. The answer must identify exact owners, bases, invalidators and result routes without reading campaign commentary or guessing from nominal types.

This assessment does not prove the current code wrong at that seam. The required design result is one source-linked binding and case table, followed by the affected whole-path proof.

### C3 — Result refinement cannot be a blanket tag mapping

The same failed application test is useful successful measurement and negative application evidence; the same physical install can complete before admission fails. Counterexample: mapping `exitCode=0` or a generic `result` tag to `satisfied` would hide these distinctions. Declare the evaluated predicate and map each operation's closed outcomes under it. Preserve refusal cause and known/unknown effects.

### C4 — Codec v2 needs one unambiguous projection route

The active [payload topology derivation](../../../build_tenants/abiogenesis/typescript/design/M03_PAYLOAD_LEDGER_EVENT_TOPOLOGY_DERIVATION.md#native-definition-material-in-durable-event-rows) declares codec v2 native definition material, and the current source implements it. The older [T289 body design](../../../build_tenants/abiogenesis/typescript/design/T289_IMMUTABLE_INSTALL_EVENT_BODIES_DESIGN.md#native-basis-input-and-ccall-result-physical-bodies-t-287--rc1) still describes exactly two native slots and v1 in its bounded earlier increment. This is not evidence that v2 has no design. The new binding should explicitly distinguish the v1 scope from the later v2 extension and source-route both, avoiding an accidental universal reading of “exactly two.”

Discriminators: v1 input/result cross-slot sharing remains lawful; native-definition slots cannot be crossed with them; missing/forward/foreign/chained references refuse; rollback never publishes a tentative source; complete decoded values and logical digests agree; physical cuts use actual encoded bytes. Proof must include historical/mixed forms where claimed.

### C5 — The latest installed stop is an identity/admission seam, not an unresolved codec measurement

[Continuation17 return-02](../T287_SANDBOX_UAT_RUN_02/operator/library-joint-proof-237/continuation-17/return-02.md) reports physical install success followed by ABG refusal of an already-held install scope under another invocation. The same installId/content/lock appeared with different target roots, candidate digests and invocations. No native Testing/C2 ran. Its current external interface does not expose a unique deeper internal first branch.

Counterexample to “just retry the workload”: repeated preparation could remake a completed physical installation and hit the same admission conflict without reaching the selected outcome. The next lawful design/path decision must consume the exact completed installation when supported or select a truly changed pair under the existing identity law. The completed physical residue and the old admitted truth remain distinct. This is a path selection issue requiring exact source evidence; no basis for weakening an admission guard was found.

### C6 — New work and exact execution resumption remain different domains

The Event Calculus and pending-consumer HOW already correct this distinction. A source-only model that treats every retained result as an instruction to restore the old call stack is too broad; a model that treats a fresh Run as exact resumption is also false.

Discriminators: preserve producer completed/consumer not started; undispatched admitted consumer; effect active or uncertain; raw result not admitted; admitted result awaiting judgment; child completed awaiting foldback; foldback awaiting parent evaluation; exhausted allowance; wrong/changed current authority. Each case needs a lawful disposition, but not every case must execute continuation in 5.0. Unsupported cases refuse truthfully under accepted Product boundaries.

## Finite completeness obligations

The new binding should make these coverage domains explicit. “Exhaustive” means no silent case within these declared domains, not proof over every possible program, physical environment or LLM behavior.

1. All fifteen Product outcome families have a route to requirements, existing computational owners, selected scenario/qualification and current evidence/residual. Do not inflate them into fifteen runtime controllers.
2. Every retained graph relation and seven C constructors has its domain, typing/cardinality, authority/effect, failure/stop, recursion/continuation and proof disposition.
3. The selected runtime/frontier phase family has a complete lifecycle/transition disposition, including all partial-effect/admission cuts; known no-effect differs from unknown effect.
4. The affected identity classes remain distinct: immutable declaration, basis, invocation/occurrence, stable workspace binding, mutable content/observation, install identity, physical target and logical/physical prefix.
5. Every affected owner admission boundary has its complete enclosing relation, basis continuity, participant joins, cardinality, refusal/effect boundary, commit unit and reconstruction. Cover every materially distinct partial publication cut or supply a declared equivalence/dominance argument.
6. Each changed component has a declared role set and maps to the accepted atom(s), composition edge or projection it realizes. Whole-family Prime review includes identity, authority, lifecycle, topology, effect and closure, not just a helper census.
7. The full affected IACS distinguishes authoritative carriers, runtime evidence, explicit public/persisted boundary, private operational metadata and subordinate payload; old/public/owned/prospective-prefix forms have a declared correspondence and non-authority rule.
8. Every material algorithmic duty has semantic disposition `existing / extension / candidate` and realization disposition `consume / local implementation / optimize / adapt / deliberate duplicate`, with reasons where equivalent machinery is separate.
9. Cold acquisition, unchanged warm handoff, changed dependency, explicit full output, close/reopen and poison/rollback each have exact validity/lifetime/cost expectations.
10. Domain, sequence and state views plus computational projection describe one system. Existing M03 views can be reused after their stale catalog cone is repaired; narrow new diagrams cover the history/continuation changed relation.
11. Every assessment outcome is predicate/basis-indexed and maps to one core value; no runtime tag substitutes for application adequacy, independent assessment or release acceptance.
12. Proof claims distinguish structure, semantic judgment, source/component behavior, installed full-path behavior, capacity and release. A fixture with invented authority cannot qualify an authentic owner relation.
