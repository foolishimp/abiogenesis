The current [Product Run Environment](../../../specification/PRODUCT.md#stdo-governed-run-environment) first paragraph requires a matching axiomatic program/index and released Axiom Indexer. The V3 source adoption has empty companion composition and native authoritative documents. This is not evidence that the existing runtime is broken on its historical admitted basis. It does mean that thorough V3 application cannot be claimed by relabeling the template or keeping its unselected mandatory cohort. The destination needs a bounded Product/requirement reprice and later implementation/proof. Technical severity: S2 against the current reconciliation claim; no implementation severity is inferred.

Such a selection binds its exact released identity, source relationship, permitted access and required evidence; native source authority is never replaced by its representation. Source-development installation or composition supplies no Run binding. Required source or selected supplementary material that is missing, inaccessible, mismatched or unpermitted blocks dependent work. Retrieval proves access, not semantic application.

## Computational calculus: what stronger design must deliver

Retain [Product Execution And Context Calculus](../../../specification/PRODUCT.md#execution-and-context-calculus) as the behavioral owner. It already states current input versus entry input, graph/frame composition, execution/admission/advancement, sufficient role context, declared selection and gaps, incremental live state, recovery, valid reuse and outcome/proportionality. A new Product-level calculus duplicating those relations would create a second owner.

The computational HOW should expose, for every selected path and material seam: the exact source/destination owners and admitted domains; the informational interpretation; the declared computation/regime; the actual technological realization and effect grant; success, refusal and unresolved outputs; preserved identity, basis, currentness, qualifications and authority; producer/consumer preconditions; retry/restart/recovery and effect-residue treatment; dependency/freshness invalidators; and proof claims with their independent oracle and support. Keep the algorithmic, informational and computational accounts linked but distinct.

Coverage can be exhaustive over an explicitly finite applicable domain: existing C constructors, retained traversal cases, semantic authority families, public entry/exit contracts, result/refusal classes and selected lifecycle boundaries. Applicability and exclusions need evidence; not every arbitrary cross-product is required. Unknown relations remain visible. Show that every selected case has an owner and specified outcome, then distinguish design completeness, source realization, integrated execution, semantic adequacy and release acceptance. A complete table is not a complete runtime; a theorem about a finite model is not a theorem about all native agents or workloads.

The most valuable discriminators include current input differing from graph entry; equal-shaped values with different authority/basis; producer completion with consumer preparation failure; performed effect with missing observation or failed admission; live/cold state equality at one committed prefix; valid reuse with changed unrelated data; invalidated dependencies; non-green assessment plus uncovered obligation; and a missing selected capability that remains a gap. These already derive from current Product law. They are scoped case-selection inputs, not a new universal test quota or runtime gate.
