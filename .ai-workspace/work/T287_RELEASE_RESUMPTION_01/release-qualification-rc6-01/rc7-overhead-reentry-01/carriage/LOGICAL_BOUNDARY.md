# Logical boundary decision

**Prefer logical owner consolidation for the complete RC7 increment.** The two-file physical-codec option in READINESS is a smaller local patch, but it preserves the cause and then needs another public projection branch. Its new physical grammar and warm/cold source machinery are avoidable if the redundant logical fields are removed at their existing owners. READINESS remains unchanged as evidence and as the description of that narrower option; its preservation premise applies to historical values, not to the future RC7 carrier layout.

The inspected owning authorities contain no requirement for the literal duplicate `before` field, a whole `task` copy in every native success/failure Result, or a whole executionBasis input inside every transport binding. `after`'s observed fact inventory is functional information; the already-retained unchanged file bodies are duplicate carriage. The current full terminal schema is HOW, but the ability to return the selected typed result is WHAT.

## Smallest complete existing-owner route

1. **Native result owner:** amend the existing success/failure carrier in `product/native_workspace_work.ts`. Remove the full `task` and derived `before` copies. Keep after observation, changedPaths, report/assessment, failure/unknown states and existing provenance. The original task and before context remain at the exact admitted input. Rejoin them through the existing CCall/execution-authority/basis owners when a consumer actually needs them; do not add a replacement task document or summary object.
2. **Admission remains complete:** the existing `nativeWorkspaceWorkResultMatches(input, output, cCallRef, observation)` boundary already receives the actual input. Keep input-dependent scope, before/after, assessment-independence and response checks there and in its existing native owner. A pure output-shape predicate cannot silently substitute for those checks after the task copy disappears. Downstream consumers obtain that established relation once, instead of re-expanding an old carrier at every hop.
3. **Context body owner:** retain the full after *fact* inventory and extend the one existing `WorksiteContextBodyMember` source domain/resolver to the exact earlier admitted **basis-input holder**, alongside its current Result holders. This is an amendment of the existing member contract, not a second schema, delta language or body store. N2/N3's initial inline context already has that immutable holder before native work. Reuse unchanged bytes through it; new/changed bytes are born in the Result. Preserve each after entry's actual fileIdentity, path, state, length, digest and directory facts. Existing member inheritance handles later contexts.
4. **Input ownership, not equal-content search:** the basis holder is the current call's admitted input source, or the input source of an already selected retained Result. It has no Run field. Extend the existing same-Run/retained-source checks by that exact join; do not admit arbitrary foreign bases. Progressed input continues through `projectTraversalInputAtPrefix`, not a fallback to graph-entry rawInput. Existing `sourceUseDeclaresMember` must resolve the selected native Result's original input instead of assuming `result.task.context` still exists.
5. **Instruction basis owner:** stop persisting the complete rawInputValue inside the binding's native execution-basis copy. Keep the existing exact basis/current-call/cursor/prefix coordinates and required declaration dependencies. The existing `deriveOwnedNativeInstructionAssemblyBasis` already rehydrates the execution basis at lines 169–170 and derives current input at 199–208; extend that same owner to accept the reference form. The live dispatch may borrow its full authenticated material. Persist only what cannot already be reacquired from its declared owners; uniquely required declaration evidence remains retained.
6. **Terminal owner:** continue returning the full typed terminal result under the revised native result contract. It is now smaller at lifecycle completion, run_result, run_replay, CLI serialization and retained command outputs automatically. A new compact Public selector is unnecessary merely to hide the removed baggage. Reuse the existing `ABG_HISTORICAL_TERMINAL_SELECTION_SCHEMA` where a handoff needs only terminal selection; do not expand it into a new summary system or use it to counterfeit the two-read result proof.

This is owning HOW/carrier re-entry, under unchanged Product/requirements. It changes prospective Result/contract digests; byte equality to an old redundant value is consequently the wrong oracle. The oracle is complete conserved task/input access, physical observations, source/authority/effect relation and result meaning through the declared existing owners, plus exact new-contract identities. Historical N2/N3 values retain their original digests and owners.

## Finite causal cone and choice

| Route | Work and limit |
|---|---|
| **Logical consolidation — recommended** | Existing native result/implementation and GTL contract; worksite member contract plus event-prefix resolver/history holder index; execution-basis/instruction assembly and binding persistence; actual native-result consumers; canonical generated contract/descriptor and affected proof. More caller migration, but one logical representation and existing storage machinery. No v4 patch grammar or extra public compact mode is needed for this duplication. |
| Physical codec + compact Public branch | Keeps old large logical objects; adds combined references/delta reconstruction and source registration across append/full/selected/cold paths, then a second output choice to avoid large serialization. Capture/hash/allocation and initial lifecycle output can remain large. It is justified only if Root explicitly selects unchanged future logical carriers or a separate measured physical-only outcome. Neither premise follows from current Product WHAT or the owner's RC7 instruction. |

The identified dependent consumers are the existing native source/reacquisition, command-execution, default-library, semantic-job/revision, instruction presentation and Event Calculus paths. Concretely: `abg/native_worksite_execution.ts`, `abg/native_work_reacquisition.ts`, `product/worksite_command_execution.ts`, `abg/default_library.ts`, `abg/semantic_job.ts`, `product/semantic_job.ts`, `gtl/semantic_job.ts`, `abg/semantic_revision.ts`, `product/semantic_revision.ts`, `abg/event_calculus.ts`, `abg/calculus/axioms.ts`, `product/builtin_semantics.ts`, plus their existing exports/declarations. This is the finite migration list, not authority to rewrite those modules generally. For example, the current worksite-effect calculus reads `value.task` at axioms line 534 and must instead use the same exact input owner; leaving it untouched would lose invalidation scope.

Retain the existing physical codec and its selected historical behavior. Preserve exact L law, already declared historical joins and original-owner replay of RC6 and other retained cuts. Do not reinterpret old values as the new carrier, restamp them or promise that every future reader accepts every historical shape. New RC7 contracts govern new production; any specifically required mixed L/current join remains explicit and tested in its existing owner.

**Decision discriminator:** on the retained N2/N3 workload, verify one initial admitted body holder, no full task/before copy in the new Result, no raw-input copy in binding, unchanged after bytes referenced through the existing holder owner, and no re-expansion before ordinary serialization. Prove current/progressed input and retained-source joins, changed-file identity and failed/unknown-after behavior, cold body access without mutable-worksite/cache assistance, and both fresh typed terminal reads under the new exact contract. Count binding/Result, lifecycle-return, two read-return and retained command bytes together. CPU and elapsed-time claims still require measurement. Reuse unaffected D5 and qualification evidence.

No new code, test, runtime or control effects were performed. READINESS.md/json hashes were checked and preserved. This supplement supplies the missing selection relation and does not start another review cycle.
