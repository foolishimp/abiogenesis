# RC5 source and evidence custody

Root operator preparation under the approved RC5 scope. This is a plan, not an
acceptance or release record. The current source checkpoint is 9f3f22b0f; F4 is
running from that checkpoint and must return before any candidate adoption.

The final local source branch will retain the exact native manual changes,
the exact admitted C2 generated contracts and manifest, and the operator inputs
needed to construct that C2 snapshot. In particular, contract seeds, the final
proof recipe, the captured three-row sample and the explicit retained-method
proof must be tracked or carried in a content-checked evidence archive. An
untracked seed directory is not a reproducible build input.

The source/build relation is checked in this order:

1. Match every granted manual source file to the actual admitted native return
   and the independently reviewed frozen snapshot.
2. Match C2's source-correspondence output to that same snapshot. Match the
   helper artifact, command results, predicates and snapshot coordinates to
   the actual admitted C2 Result, then match its generated files and archive.
3. Conjoin the independent source review, actual affected proof, native UAT
   and fresh result/replay. Preserve method-01's first C2 failure and r2's
   eighteen passes plus indeterminate UAT as distinct historical outcomes.
4. Adopt exact generated bytes under a separately recorded Root Writer action,
   checkpoint the source, and verify that the cut's archive and source inputs
   remain those selected by the conjunction. A clean isolated reproduction
   may rebuild/generate/pack for byte comparison without repeating qualification.
5. Allocate fresh RC5 release/install roots through the existing Product owners
   only after the exact final input manifest and absent destinations verify.
   Compare every installed payload to the authenticated archive. Retain the
   archive, lock, installer receipts, inventory and local unqualified claim.

Evidence copies keep original bytes and hashes. The closed RC5 campaign log
may be compressed as a byte-exact copy for source custody; the original log and
its device/inode/path-bound authority remain untouched. Such a copy supports
inspection and byte reconstruction. It does not manufacture an admission or
claim that an original machine-bound reopen coordinate works on another host.

The complete native timing report separates artifact verification, maintained
SDK setup, initial selector launch, native task admission to process launch,
native work, the in-Run transition to C2, C2, UAT and fresh cold projections.
Time between separately selected coding tasks includes Executive evaluation,
earlier failed proof, operator input repair and preparation. It is reported
separately and is not presented as runtime overhead or a causal speedup.

No final source merge, push, tag, global selector change, whole Product
qualification or stable-release claim is selected. The current main checkout's
dirty/untracked work and all immutable RC4 releases remain preserved.
