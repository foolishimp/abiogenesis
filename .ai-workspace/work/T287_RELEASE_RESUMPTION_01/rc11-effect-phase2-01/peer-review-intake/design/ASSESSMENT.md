**Concrete release order.** Establish ownership of the child/lifetime before fallible capture/timeout setup. A synchronous spawn refusal remains no-child; partial post-spawn acquisition failure needs an explicit finite cleanup path, not an unowned child. Define one settlement operation over the existing lifetime: request its existing finite termination if needed, then await its completion. It must never await a still-live child's completion before any path requests cleanup. Register the ownership guard immediately. Every subsequently acquired capture/listener/timer resource's release first crosses that same settlement barrier, then disposes its own handle; the ownership guard also settles. Thus Scope LIFO, partial setup failure and interruption cannot detach capture before physical completion. Repeated barrier calls reuse the same idempotent lifetime and completion; they do not allocate another supervisor, deadline or completion Promise. Normal body execution already awaits final facts, so these release barriers are immediate on that path. Retain the existing synchronous direct-exit capture cut; this is separate from final listener removal.

An alternative single ordered resource release is equivalent only if it proves the same partial-acquisition coverage. Scope finalizers must preserve the retained primary failure; a secondary detach/release failure must not replace it, while a sole finalizer failure remains failure. Inert Node error guards through natural close are not ordinary removable listeners. The lifetime's own finite deadlines support the wait; Effect interruption does not prove absence or cancel arbitrary pending I/O. Keep emergency process.exit behavior explicitly outside ordinary Scope-finalizer guarantees.
