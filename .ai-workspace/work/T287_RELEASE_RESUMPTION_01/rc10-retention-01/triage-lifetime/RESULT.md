## Recommended smallest lifetime design

Use **explicit disposable computation scopes owned by the existing run invocation operation**, joined to its exact store and admitted invocation/basis identities. This is permission to retain work, never a new runtime status. Do not derive terminal status again inside the row checker (calculus liveness itself consumes that checker, creating a recursion hazard), and do not key anything by ambient process or GC survival.

- Activate scoped retention only after the run owner has acquired its actual resource and selected the invocation/basis. Initial admission can be checked cold before activation. For continuation, use the existing prepared original invocation/basis, not the new public continuation operation's unrelated invocationRef. Descendant bases inherit the admitted invocation relation; preserve exact basis membership.
- Place the full checked row memo in this existing derivation territory, with exact per-operation disposal handles. An operation may retain only its selected admitted invocation/bases, not every historical row it happens to read. Genuine overlapping operations must have separate ownership handles: finishing one removes only its entries; shared eligible facts need bounded owner references. This is an ownership relation for a cache, not a durable status/tombstone registry.
- Release the operation's retained facts in its existing Effect finalizer on success, refusal, failure, cancellation, interruption and nonterminal return. Releasing on held/gap/yield is lawful computational disposal, **not** a claim that the durable invocation is terminal. A later continuation reacquires from admitted history. The finalizer is stronger than terminal-only cleanup and covers refusal before opening a GraphCall.
- Historical/replay reads without an active exact eligibility handle remain cold and non-retaining in the session cache. Retaining an old prefix or requesting an old cut must not create a handle. A historical read while another invocation is active must not put the old invocation into that active cache.
- The same rule must prevent `RuntimeHistory.#verifiedBodies` from retaining basis payloads beyond that scope. For ineligible/historical basis rows use the existing consumer-local `selectedBodies` map/consume lifetime; do not replace the durable location/envelope index. Keep other event families unchanged unless a concrete additional body path is found. No claim of globally bounded heap follows.
- Physical resource close/abandon must dispose all relevant body-bearing computation scopes before returning or throwing. Old nominal prefixes may still read immutable evidence but cannot reopen retention. Rollback disposes the old generation; any still-running operation must explicitly reacquire eligibility on the new authentic generation before reuse. Old prefix reads continue their existing refusal.

Caller-held objects are outside these gauges: a caller retaining a returned ExecutionBasis, materialized event vector, call/request, terminal result or replay output may keep the same raw input alive. Owner disposal removes the selected cache roots; it cannot revoke caller references and is not heap reclamation. No memory-release claim follows merely from zero retained owner rows.

This recommendation preserves the current full return contracts and reference identity for repeated reads during the same genuinely active scope. It intentionally stops promising strict reference equality for completed historical calls: equality/refusal semantics remain the contract. Update OWN-01, which currently proves historical retention after all three Runs have finished.

Bound precision: `retainedRows <= openInvocations` is true only for the one-basis-per-call fixture. Production allows root, child and continuation bases under one invocation. State the general bound as retained eligible basis rows belonging to currently open computation scopes; do not disguise that distinction. If Root requires a strict live-GraphCall bound for long-running recursive/fan-out invocations, add child-scope disposal at existing HoG child return/foldback owners (`completeRecursionChildUsing`, `completeOwnedWorkflowLocus`) and their failure paths; that is a materially wider proof than the serial-call F1. Do not claim that stricter bound from this triage.

Leaner fact alternative: retain only successful row validation witnesses/digests and rebuild the shallow record from the currently acquired event. This can preserve avoided raw-admission/body-hash work, but by itself loses checked-record reference identity, still leaves RuntimeHistory body retention, and metadata can still grow forever. It is not the smallest complete F1 repair while active-reference reuse is selected. WeakRef makes reuse nondeterministic and does not establish the requested disposal boundary.

## Proof and observations

Add internal non-barrel observation snapshots. `retainedRows` is the number of distinct successfully checked full row facts strongly held by the selected cache at observation time (gauge, not cumulative admissions). `retainedPayloadBytes` is the sum of deterministic UTF-8 canonical byte lengths of rawInputValue for those retained rows; record the metric once when eligible retention is established, never by reserializing on every snapshot. It is logical serialized data, not V8 object size, allocated bytes, unique shared-object memory, RSS, or JS heap. Separately expose history-owned retained basis-body rows/bytes, or use a clearly defined union by eventId:ordinal so the two retaining roots cannot hide each other or double-count. Retain rowAdmissions/bodyDigests as work counters. Keep process.memoryUsage/optional heap observations separate and report GC conditions and parent/child coverage.

Acceptance, using installed deterministic fixtures and authentic owner admission:

- Fifty sequential calls over one held resource: after every actual operation return/finalizer, both basis retaining owners return to zero for completed calls, including alternating sizes. Snapshot during active calls shows rows retained/reused by identity and no repeated row/body work. Historical result/replay and earlier-cut queries after each completed call preserve exact results and do not raise retained gauges.
- Mixed terminal outcomes: actual success, typed refusal after basis admission, admitted runtime failure, interruption/cancellation, and failed output/recovery where finalization still runs. Before-basis refusal is a separate zero-row case. A held/gap return disposes computation, and authentic continuation reacquires and preserves its existing runtime semantics.
- Overlap: hold A open, run/finish B, observe A's exact record identity and reuse survive while B's rows disappear; historical reads for completed C cannot add retained rows. Then finish/cancel A and observe zero. Use deterministic controlled leaf promises/owners; do not invent concurrent append authority or replay stale selections.
- Real rollback after a tentative row was observed: suffix entries and old-generation eligibility disappear, old selection refuses, surviving predecessor checks cold, and a later different row at the same ordinal cannot borrow the prior fact. Closure plus old-prefix historical read and a genuine reopen must not repopulate the former scope.
- Preserve absent/earlier-cut/copy/foreign/malformed refusal, exact membership/cardinality and digest checks. Duplicate input remains `many` before any cache lookup. F2 can be corrected by deleting the false word “duplicate”; add the duplicate case only if used to prove the changed admission/cache boundary and then report its actual result. No residual is closed by its planned test.

Affected regression set: held-owner-fold reuse, owned-call-reference, held-prefix, ordered reconstruction, calculus state transfer, Event Calculus owner continuation, runtime-failure diagnostic, terminal-quiescence owner, native semantic revision, C0 post-publication failure and relevant project-read/fresh reconstruction fixtures.
