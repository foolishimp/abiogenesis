`MEASUREMENTS.json` binds the exact B11 Run, executing RC2 release/source, candidate RC3 artifact, event kinds, exact source nesting, measured actual-process and between-process intervals, and the cold diagnostic. The closed prefix was independently re-read after profiling: 1,339,885,116 bytes, SHA-256 `9132990646773460f5b1981c4b5ddc721333bdba465ff1655eba61a8ac2886d8`, device 16777231 / inode 668846706, matching `CLOSED_PREFIX.json`. The closed log was scanned once with `python3 scripts/b11_measure_events.py`, using mmap to count whole physical event-line lengths by `kind`; 4,525 complete events were seen. `scripts/b11_body_measure.py 2982`, `1879`, `2929`, `3003`, `4440` parse only those exact event ranges and measure compact UTF-8 JSON subtree lengths. `scripts/b11_context_measure.py` compares all 965 entries of the three C2-nested contexts; identical means JSON object equality. The 961 selected C2 source paths and four separately declared operator-input reads form the 965 observed paths. The three embedded contexts are authority-bearing source/result data; these measurements alone do not authorize dropping them.

For the warm-cache micro-discriminator, run `NODE_OPTIONS=--max-old-space-size=4096 /opt/homebrew/Cellar/node/24.7.0/bin/node scripts/b11_cpu_discriminator.mjs`; `CPU_DISCRIMINATOR.json` captures the second run, after an initial run whose tool output was truncated. It reads and hashes the exact admitted 124,233,329-byte event and checks the actual `valueDigest` with installed RC2 `sha256Canonical`. Its 698,211-byte comparison is a deliberately incomplete metadata-only diagnostic projection of the same three path/digest sets; it is not a schema-equivalent Result, a replacement store or a proposed authority. The single full canonical hash measured about 224 ms, so one hash cannot by itself explain the 1,274.165 seconds between actor processes.

For one separate cold-read diagnostic, `CLOSED_PREFIX.json` was extracted from `attempt-013/after-run-resume.json`. An isolated process was run with a 90-second timeout, using `/opt/homebrew/Cellar/node/24.7.0/bin/node --max-old-space-size=8192 --cpu-prof --cpu-prof-dir=/private/tmp/b11-profile scripts/b11_read_prefix.mjs`. It performed the existing installed RC2 `readRuntimeEventsAtDurablePrefix` exactly once, returning 4,525 events in 17.553s wall / 18.346 CPU-s and reporting max RSS 4,993,168 KiB. The host had 128 GiB physical memory and approximately 86% free by `memory_pressure` just before this diagnostic; prior reads warmed the cache. CPU profiling was enabled, with no matched unprofiled run. Raw local profile `local-raw/CPU.20261101.124913.70952.0.001.cpuprofile` is 460,420 bytes / SHA-256 `6918ce3a97e0409d877c09bf631accaf5ac810a3f4c59e5d1e4af55d82a9d443`; keep the bulky raw profile local and use the index in `MEASUREMENTS.json`. Inclusive sample attribution overlaps; leaf sample weights are sampling evidence, not an end-to-end breakdown.

Actual actor start-to-exit intervals total 955.357s; disjoint intervening intervals to the next actor or closure total 1,274.165s. They include owner work, scheduling and I/O and are not an all-CPU measurement. The provider-reported 920.454s overlaps actor lifetimes and must not be added to them. One cold 17.553s read proves that full cold validation is material, but the number and provenance of cold reads during the actual Run were not profiled. Existing RC2 `RuntimeHistory` has a verified-body cache, so a warm retained body must not be described as necessarily re-decoded on every access. The original selected B10 Run and witness004 are different workloads; their elapsed values are comparisons, not controlled performance experiments.
