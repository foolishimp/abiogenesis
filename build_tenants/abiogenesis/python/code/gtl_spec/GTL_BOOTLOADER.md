## 1. Core Position

GTL.TypeScript is the sole program language. A GTL composition is a Program.
GraphFunction is the sole named callable work contract and replayable graph-
template carrier.

The stable path is:

```text
GTL.TypeScript
  -> native TypeScript checking
  -> raw admission
  -> non-lowering GTL whole-Program validation
  -> Module and catalog admission
  -> Program start or member GraphFunction call
  -> direct HoG traversal
  -> exact F_D | F_P | F_H leaf owner
  -> ABG admission and replay-derived runtime truth
```

GTL is graph-first, composition-first, recursion-capable, higher-order, and
declarative. HoG executes admitted GTL. ABG owns runtime admission, events,
replay, lineage, continuation, correction, and closure around that execution.

## 2. Structural Axioms

1. A GTL `Program` is an admitted graph composition owning topology, starts,
   callable membership, compute composition, policy, results, and proof law.
2. `Graph` is declared or materialized topology.
3. `Node` is a typed local locus of graph meaning.
4. `GraphVector` is an internal typed transition boundary, never a public
   callable or independent runtime plan.
5. `Context` is an externally located, snapshot-bound constraint dimension.
6. `Operator` performs declared work through an implementation seam.
7. `Evaluator` checks, diagnoses, or attests a boundary.
8. `Rule` passively declares what must hold.
9. `GraphFunction` is the sole named callable work contract. It is not the whole
   Program.
10. `RefinementBoundary` is an explicit lawful refinement or synthesis
    boundary.
11. `CandidateFamily` publishes alternatives without selecting one.
12. `Module` is the publication boundary.
13. `Job` is a durable semantic work contract over published GraphFunctions; it
    does not replace Program starts or membership.
14. `Role` is a semantic capability class, not a concrete worker identity.

Workspaces, validators, generated indexes, catalogs, SDKs, CLIs, adapters,
workers, plugins, and ABG runtime carriers are not rival Program authorities.

## 4. GTL / HoG / ABG Boundary

GTL declares:

- Programs, starts, callable membership, topology, policy, results, and proof
  obligations;
- GraphFunctions and their typed interfaces and replayable templates;
- graphs, nodes, vectors, contexts, interfaces, and attributes;
- graph and C algebra;
- operators, evaluators, rules, roles, jobs, hooks, and asset surfaces;
- refinement, candidate, synthesis, recursion, termination, foldback, fan-out,
  fan-in, and bounded sub-work law;
- compute regimes and selected composition declarations; and
- Module publication, contracts, compatibility, and implementation seams.

The GTL validator judges whole-Program law without lowering. It may return
typed diagnostics, canonical serialization, and subordinate indexes. It does
not select runtime work or emit runtime facts.

HoG:

- directly traverses the original admitted Program and materialized
  GraphFunction graphs;
- follows declared graph and C relations; and
- may derive invocation-local cursors, frames, queues, and caches that remain
  subordinate to one Program and invocation.

Exact implementation owners perform only declared leaf effects.

ABG owns:

- invocation, graph-call, frame, attempt, and workspace-transformation
  admission;
- event, payload, result, evidence, judgment, and transition admission;
- replay-derived runtime state and projections;
- lineage, provenance, continuation, retry, human hold, block, correction,
  re-entry, and closure; and
- admitted runtime policy and assurance truth.

HoG advances declared topology. ABG admits what occurred and derives lawful
runtime state. ABG does not interpret or execute the graph.

## 5. Evaluator Regimes

| Regime | Meaning | Authority boundary |
|---|---|---|
| `F_D` | Total mechanical function or predicate over a declared closed domain | Open-world semantic judgment is not deterministic merely because code performs it |
| `F_P` | Bounded semantic construction, diagnosis, synthesis, repair, ranking, or evaluation | Output remains candidate material until admitted and cannot certify closure |
| `F_H` | Attributed human approval, rejection, choice, escalation, or ambiguity resolution | Response crosses typed admission and cannot override deterministic invalidity |

One regime may consume another regime's admitted evidence. It cannot impersonate
the other regime or inherit its authority.

When `C` denotes selected `abg.fn_composition`, it is notation over a selected
composition contract, not a topology object or runtime carrier:

```text
transform.C   -> candidate/evidence proposal
evaluate.C    -> evaluation-set proposal
consequence.C -> projection proposal
```

ABG admission is the boundary at which lawful proposals become runtime facts.

## 6. Recursive Runtime Contract

Operational recursion requires:

- a declared recursive GraphFunction relation;
- explicit termination, foldback, lineage, parent re-evaluation, and bounds;
- exact child GraphCall and Frame identity;
- admitted child result and evidence;
- foldback through the declared parent contract; and
- replay-derived continuation or closure.

Child closure does not certify parent closure. `C.retry` repeats one bounded
attempt at the same locus; it is not graph recursion. Frame-local state cannot
escape into global publication or become a hidden queue/controller.

## 7. Runtime Truth Rules

1. ABG is the sole runtime event-admission authority.
2. Events are append-only admitted facts.
3. Replay reconstructs and projects; it does not author truth.
4. Worker returns, plugin payloads, logs, files, and terminal text remain
   candidates or observations until admitted.
5. HoG traversal state remains subordinate to the admitted Program and
   invocation.
6. Correction preserves history.
7. Continuation and closure derive from admitted Program law and replay state.
8. SDK, CLI, adapter, and read-model surfaces do not select traversal.
9. A private event writer, rival catalog/runtime, controller, or closure ledger
   is prohibited.
10. Correct output through a bypass does not prove the installed causal path.
