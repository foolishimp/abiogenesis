## 2. Position

The next TypeScript `M04` wave does not start from Python shell flags,
multi-tree copying, or installed Python package layout.

It starts from the paused Python reference design truths:

- install/bootstrap is a delivery boundary below kernel semantics
- installed runtime roots and workspace bootstrap are explicit product-facing
  delivery truth
- the installer may materialize files and directories, but it must not define
  runtime law or closure doctrine
- package/runtime identity must be explicit rather than hidden in ambient
  script defaults
- install proof is more than "the script ran"; it must verify the declared
  installed surface

## 3. Preserved Boundary Truth

The next TypeScript `M04` slice preserves these truths from the Python line:

- the installed root is explicit and inspectable
- workspace bootstrap roots such as `.ai-workspace/events` and
  `.ai-workspace/runtime` are explicit delivery artifacts
- package/runtime identity remains explicit delivery input truth
- install verification is explicit and typed rather than inferred from shell
  success alone

## 4. Demoted Python Delivery Detail

The TypeScript line intentionally demotes these Python-shaped details to
delivery binding or deferred concern:

- Python module vendoring into `.genesis/`
- methodology/standards copying
- AGENTS/CLAUDE bootloader injection
- Python-specific `PYTHONPATH` bootstrap semantics
- archive finalization and proof-log capture
- CLI packaging or binary artifact shaping

Those may reappear later as bootloader or installed sandbox surfaces, but they
do not define the first TypeScript install/bootstrap boundary.

## 5. First TypeScript M04 Install/Bootstrap Target

The first TypeScript install/bootstrap slice should realize only:

- one admitted public install/bootstrap request carrier
- one admitted installed-runtime package contract carrier
- one pure install/bootstrap plan over explicit delivery truth
- one bounded effect shell that materializes:
  - target root
  - installed `package.json`
  - one package-first bootstrap entry
  - one install manifest
  - one `.ai-workspace/events/events.jsonl` file
  - one `.ai-workspace/runtime/` directory
- one closed public install/bootstrap outcome family

This first slice should **not** widen into:

- bootloader/project-facing delivery orchestration
- archive or proof-log copying
- live sandbox execution
- runtime semantic reconstruction
- automatic package install or external package manager invocation
