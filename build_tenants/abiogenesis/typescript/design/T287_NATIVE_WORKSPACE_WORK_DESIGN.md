## Effect and observation

leaf port checks the selected admitted prefix, invocation grant, execution
basis, implementation resolution, C-call and declared effect. The selected
implementation reobserves the context before launch and refuses stale or

trusted-developer workspace boundary, not hostile-workstation containment.

The native host owns its internal coding/test iteration. The framework neither
prescribes a coding loop nor interprets tool transcript text as filesystem
truth. On every received transport terminal, including failure, the selected
owner observes actual assets again with the same declared scope and bounds.
The output carries task, before/after observations, actual changed paths,
short report and exact C-call/authority/transport provenance. Directory
membership changes caused by permitted descendant writes are supported;
unrelated changed files remain scope violations. With empty write roots every
change is a violation. Writes in W\R are not observed; they are neither
`changedPaths` nor violations. Observation failure retains an explicit unknown
after state, not an invented unchanged state or rollback.

Timeout, native nonzero exit, missing/malformed report, observation failure or
scope violation remains failure, with available partial edits retained. A
report cannot prove completion, authorize another effect, or select a route.
ABG admits its ordinary transport evidence and typed result/refusal; no private
event writer or new event kind is introduced. Failed unlaunched preparation
uses the existing undispatched owner-refusal route. Durable admission failures
retain the existing failure behavior; physical work is not represented as an
atomic rollback.

One conservative impact relation in `abg/native_work_effect.ts` defines what an
authenticated native cause may have changed at its canonical worksite root:
impact = observed changed paths ∪ (W\R). A known after-state supplies
`changedPaths` inside R; W\R is unobserved territory and is impacted whole. An
unavailable after observation and an admitted post-start unknown
process/transport effect impact all of W. That relation is not evidence that
any particular file changed or remained unchanged. EC (`abg/calculus/axioms.ts`)
and the currentness gate (`abg/native_worksite_execution.ts`) both consume it
with exact path/subtree overlap. An exact fact path is impacted by an equal
changed path or by lying in W\R. A selected subtree is impacted by a changed
path inside it or by intersecting W\R. An impact retires the affected earlier
C0 current-observation facts at the same canonical root. Facts of presence and
facts of absence are retired alike, because immutable bindings do not partition
a file. Observed-unchanged R facts and territory outside the impact remain
current, including every fact under an empty read-only scope. The relation
does not manufacture C0 effect provenance, C0 successors or `changedPaths`
entries. Native after-state stays available in the ordinary admitted result and
replay. Unknown after-state and the original failure remain explicit; no
successor observation is manufactured.

## Protected write roots

Protected roots P are the WorkspaceBinding roots plus the `installedRoot` of
each Product install in the exact-prefix workspace environment. A write root
w ∈ W overlaps P when w equals, encloses or lies inside some p ∈ P. All three
overlap classes refuse the task before assembly and provider dispatch. R keeps
its existing legitimacy and observation. An ordinary w outside R that meets no
p is admitted.

The 2026-11-13 T-292/T-293 B-05 HOW re-entry (Writer
`T292-TD85N-CODEX-02`) applies the shared read-only
[planned protected-root separation](T287_W2_R3_C0_MUTABLE_WORKSITE_CAUSALITY_DESIGN.md#planned-protected-root-separation-t-293-b-05)
computation before assembly/provider dispatch. Its three results are `separate`,
`overlap`, and `indeterminate`. Equality, enclosure and containment refuse;
unproved possible overlap returns existing `invalid_coordinate` with explicit
uncertainty, not an assertion of an observed alias. Canonical existing branches
can establish separation. The ASCII missing-name discriminator applies only
to the cited Darwin APFS and Linux ext/tmpfs name models identified by read-only
`statfs`; Windows trailing-dot/space and short-name behavior, FAT, unknown
filesystems and unproved Unicode comparisons do not supply that evidence.
Case-sensitive case-only names and different Unicode missing siblings can be
conditionally indeterminate. This records a missing physical-coordinate premise,
not a permanent filename prohibition, changed binding policy or new dependency;
stronger later evidence can admit them. Proven-disjoint siblings and nested write
roots retain the positive law above. No cleanup after dispatch can substitute
for preflight, and actual later effects retain their existing fact/result law.

The relation has a path reading and a physical reading, both in the existing
worksite owners:

- Path (`product/worksite_effect.ts`): `constructWorksiteTerritory` checks the
  binding join and territory URI, and refuses containment in a declared
  binding root. `protectedWorksiteWriteRoot` adds the enclosing direction.
  Read territories keep containment only, so R = `.` stays valid.
- Physical (`product/worksite_operations.ts`): `checkWorksiteWriteRoots`
  resolves P through `worksiteReadRoots`, which covers binding and install roots
  through `plannedCanonicalPath`. It checks the lexical target with
  `checkedWorksitePath`. It then resolves w physically and refuses either
  containment direction:
  - an existing file resolves through its canonical parent;
  - a directory or missing path resolves through `plannedCanonicalPath`;
  - a link at any existing component refuses.

## Context body carriage (P1)

A worksite context's identity is its workspace authority basis and binding,
read roots, bounds and ordered path/state/file-identity/length/content-digest
entries. `observationRef`/`observationDigest` hash exactly those facts; the
storage location of a file body is not part of identity. Before/after
comparison, `changedPaths` and currentness compare these facts. The C2
reacquisition request owner compares the physical identity entries of the
freshly observed context with the source `after` entries. The request keeps
that fresh observation; no owner substitutes the source carriage.

`observeWorksiteContext` births every file body inline. A file entry is either
inline (`encoding: "base64"`, `bytes`) or an admitted member
(`encoding: "admitted_member"`, `member: {resultRef, resultDigest, path}`). A
member names one earlier inline entry of a committed `c_call_result_admitted`
value at a declared native context coordinate: `framed_synthesis_task.context`,
`native_workspace_work_task.context`, and `task.context`/`after` of a native
observation or failure. The pure guard hashes inline bodies once per immutable
value and checks member shape only.

The held Event Store prefix owner (`abg/event_prefix.ts`) derives an in-memory
selector `native-context-body:<digest>` from those coordinates of committed
success/failure Results. It is a hint, never read authority. After a producer
reobserves current W, `reuseWorksiteContextBodiesAtPrefix` replaces each inline
body already held inline by an earlier committed Result of the same Run, path,
digest, authority basis and binding with that member. A holder in another Run
is used only when the consumer's admitted retained-source use declares that
exact member (below). Changed and new bodies stay inline and are born by the
Result that admits the context. Validation
candidates are never holders; an unavailable derivation keeps bodies inline.
`resolveWorksiteContextBodyAtPrefix` reads one selected member at a raw ingress,
presentation or cold-recovery boundary. It rejoins the committed Result, its
digest and Run, the declared coordinate, holder basis/binding, the consumer's
path, digest, read roots and grant, and the held bytes, and otherwise refuses
with `malformed`, `missing`, `pending`, `foreign`, `tampered`, `stale` or
`denied`.

The native implementation reobserves W before dispatch and compares identity.
`before` is the admitted task context. `after` keeps the task's members for
unchanged files and births changed bytes inline once. The governance
preparation owner (`abg/default_library.ts`) applies producer carriage to its
fresh observation; selector source matching, obligation quoting and the
selector presentation read declared members through the owner reader for their
own Run and, under admitted retained-source use, for the selected source
members (`governanceContextBodyUse`). Semantic job/revision contexts remain inline births; their byte
consumers refuse a member.

Current limits: the observation's `task` is the exact admitted input and the C2
`sourceNativeWork` is the exact admitted observation, by the exact-equality
owners `abg/native_worksite_execution.ts` and `abg/execution_basis.ts`. Those
copies carry metadata and any inline births of the copied value. A direct native
task whose context is itself a birth repeats those bodies in its observation.
A replacement Run observes and births its own first context, and a
predecessor-Run holder refuses `foreign`. A registered-selection pending
execution resumes in its own Run, so its selected native context -> member ->
committed holder resolves through the unchanged same-Run resolver
([HOW](./T287_PENDING_CONSUMER_CONTINUATION_DESIGN.md#retained-context-bytes-and-default-library-consumers)).
The one cross-Run holder relation is retained-source use: the consumer's
admitted `sourceResultBasis` state -> a selected native observation Result ->
its `task.context` member -> committed holder
([HOW](./T287_PENDING_CONSUMER_CONTINUATION_DESIGN.md#retained-source-context-bodies-across-runs-r2)).
`after` declares no member for another Run. Exact-intent payload
recovery carries no native task context and is a separate proof. The packaged
C2 renderer `product/worksite_command_execution.ts` is a pinned run-environment
member. `gtl/worksite_command_execution.ts` pins its full emitted digest and
length and the renderer span, and the manifest generator verifies both before
publication. Any change to the renderer source reconciles those pins against
the actually emitted member.

Pre-P1 context values hashed their identity over inline bytes. They are not
current validated inputs. For the native work input, the instruction-assembly
owner refuses such a value `unsupported_selection` before any actor
([M03 boundary](./M03_INSTRUCTION_ASSEMBLY_DERIVATION.md#current-native-binding-and-material-lifetime)).
No schema version, decoder, failure class or history migration applies, and
generic history reads are not promised to reject every embedded pre-P1 value.
Pre-P1 logs remain readable with their pinned earlier builder.
