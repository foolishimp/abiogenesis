# T-287 Native Workspace Work

This bounded design reframe realizes Product's native F_P and current-workspace
Worker → Evaluator → Consequence grants (PRODUCT.md 516–565, 640–659, 850–858)
under STDO v2.5.1-rc.1, Derived Worker, Reuse/Foundation and computational
whole-path evaluation; the project frame is F-END-TO-END-INTERFACE-INTEGRATION.
It preserves GTL declaration, HoG traversal, ABG admission, and independent
consumer judgment. C1 remains available when its closed construction protocol
is selected. It is not compulsory on this path.

## Declared boundary

`constructNativeWorkspaceWorkModulePublication(artifact)` publishes the ordinary
F_P leaf, `graph-function://abiogenesis/worksite/native-work@5`, with the declared
`effect://abiogenesis/worksite/native-work/v1` effect and existing run/child
closure relations. `constructNativeWorkspaceWorkTask` binds the exact admitted
workspace authority, binding, invocation capability grant, and actual bounded
context observation to consumer data: outcome, instructions, read-first paths,
write roots and checks. All paths are normalized, inside the observed readable
scope; required read-first assets exist. Empty write roots permit independent
read-only assessment. Instructions and checks cannot widen typed write scope.

The existing ABG instruction owner derives one request from the exact selected
C-call and admitted input. Where a run environment is selected, its existing
constructor role/context policy supplies the selected immutable standards and
access evidence. It must permit current-worksite context. The prompt routes
the host to actual assets; the retained machine assembly binds their exact
observation and input identities. No cumulative semantic-stage envelope,
replacement-text payload, task-specific target rule or second context service
is introduced. Native reports are the short closed `{summary, gaps}` carrier. Its published
`abg.raw_result_contract` declaration includes the report contract in the exact
required execution closure, using the existing native-worker convention.

## Effect and observation

HoG obtains the existing closed leaf execution authority before dispatch. The
leaf port checks the selected admitted prefix, invocation grant, execution
basis, implementation resolution, C-call and declared effect. The selected
implementation reobserves the context before launch and refuses stale or
unavailable input. ABG's existing native host/transport runs at the exact
`A.canonicalRoot`, with ordinary local read/edit/search/shell tools. Installed
Product/runtime resources remain outside the granted worksite. This is a
trusted-developer workspace boundary, not hostile-workstation containment.

The native host owns its internal coding/test iteration. The framework neither
prescribes a coding loop nor interprets tool transcript text as filesystem
truth. On every received transport terminal, including failure, the selected
owner observes actual assets again with the same declared scope and bounds.
The output carries task, before/after observations, actual changed paths,
short report and exact C-call/authority/transport provenance. Directory
membership changes caused by permitted descendant writes are supported;
unrelated changed files remain scope violations. With empty write roots every
change is a violation. Observation failure retains an explicit unknown after
state, not an invented unchanged state or rollback.

Timeout, native nonzero exit, missing/malformed report, observation failure or
scope violation remains failure, with available partial edits retained. A
report cannot prove completion, authorize another effect, or select a route.
ABG admits its ordinary transport evidence and typed result/refusal; no private
event writer or new event kind is introduced. Failed unlaunched preparation
uses the existing undispatched owner-refusal route. Durable admission failures
retain the existing failure behavior; physical work is not represented as an
atomic rollback.

An admitted native success or failure with observed edits retires earlier C0
current-observation facts only for exact changed file paths at the same
workspace binding. It does not manufacture C0 effect provenance or C0
successors. Unchanged/absent paths retain their facts. Native after-state stays
available in the ordinary admitted result and replay. An unavailable after
observation is not evidence that any particular file changed or remained
unchanged. The same authenticated result retires earlier C0 observations in
the task's declared writable scope at the same workspace binding, using the
existing exact-path/descendant/root scope relation. This includes observations
of absence inside that scope. Facts outside the writable scope and facts under
an empty read-only scope remain unaffected. Unknown after-state and the
original failure remain explicit; no successor observation is manufactured.

## Consumer judgment and qualification

The leaf's mechanical judgment means only that the declared native work
boundary returned an admissible observation. Neither an empty `gaps` array
nor a successful process proves domain correctness. A consumer declares its
own evaluator, input adaptation and consequence through ordinary GTL and
Product semantics. At a workflow/recursion child entry, the existing admitted
closure selects the callee GraphFunction publication's exact installed semantics
binding and a separate leaf port. Each port retains one authentic Product
projection; providers are never unioned or probed for matching values. The root
retains its resolved Program semantics owner. A declared external provider must
have one exact compatible required publication/install witness. Absent or
ambiguous ownership refuses. The saved parent port retains the parent's predicate
and continuation semantics when the child folds back. It may route an evaluation failure to a new native task,
then evaluate the actual artifacts again. Independent semantic assessment may
use this same leaf with no write scope. No core task-specific evaluator or
automatic recovery route is added.

## Declared typed assessment

The optional `assessment` selection on the native task selects the separate
`graph-function://abiogenesis/worksite/native-work/assessment@5` callable. Its
Program is separate; the original constructor Program, role membership and
short-report path retain their meaning. Assessment requires empty write roots
and the admitted Run environment's actual `assessor` role/context, including
current worksite access. The same F_P implementation, native tools, physical
authority, transport and before/after observation owners apply.

The consumer declares an output contract and immutable `schema_asset` through
the existing Product install convention. Its selected root or a callable
reachable in that root's execution closure declares that exact contract via
`abg.raw_result_contract`. An unrelated callable's declaration is insufficient.
The task selects the contract, schema owner and exact
schema bytes; assembly matches these to the admitted Program publication and
installed asset. The leaf's raw-result preimage check repeats the exact
selection against the required closure before ordinary raw/result admission.
Missing, ambiguous, different or invalid schema evidence refuses. This does
not let a task invent an undeclared response contract.

The schema owner retains its prepared validator with that exact admitted immutable schema for the asset object's lifetime. Repeated response-schema projection of an unchanged immutable asset reuses the same schema; selector identity checks and each resolver's actual installed-byte/declaration checks still execute. Result parsing reuses that preparation without changing strict draft-2020-12/full-format validation or raw I-JSON refusal. Changed assets, copied schema objects and standalone caller schemas establish their own preparation; no content-keyed registry or caller coordinate supplies authority. Catalog declaration application may resolve a multi-asset reference closure and remains a separate validation basis.

Before dispatch, the authenticated native assessor selects ordinary result-text
presentation. Its work order displays the full original admitted JSON Schema
and asks for one matching JSON object as final result text. The Claude host
receives no `--json-schema` hint for this presentation: no dialect or material
vocabulary is translated or deleted. The request retains the original schema,
contract and schema digest; the existing stream parser extracts the ordinary
result text and ABG independently validates it against the authoritative
schema. Prompt, assembly and transport identities bind the changed bytes and
arguments. Only an actually requested host schema tool receives the synthetic
`StructuredOutput` protocol exemption. The constructor's short-report path,
native tools, supervision and failure handling retain their existing meaning.

The task binds source paths/digests, candidate path/digest, rubric path/digest
and selected producer result/invocation identities to its observed context.
Selected files must exist at those exact digests and be read-first assets.
They may be explicitly selected existing assets; a new native-work author
result is not required. Producer coordinates are historical evidence selected
by the consumer, not a transplanted execution authority. The consumer remains
responsible for the provenance claim made by that selection. Core enforces a
fresh assessor C-call/actor invocation distinct from the selected producer.

The consumer's self-contained closed JSON Schema fixes its result kind; its
judgment fields and residuals remain consumer meaning. Core requires no
`basisDigest` field or digest echo in the raw semantic result. Deterministic
identity binding belongs to the admitted task, exact before/after observations
and native provenance already carried by the existing observation. The public
`nativeWorkspaceAssessmentBasisDigest` helper remains available for callers
that need that deterministic coordinate; it imposes no raw-result field.

The owner retains the schema-valid raw object unchanged as
`observation.assessment` with `report: null`. It does not insert, delete, repair
or rewrite a consumer field. A consumer may declare its own `basisDigest` or
other field, which remains governed by that exact installed schema. Prompt
rendering displays the complete declared schema and exact subject context,
without adding a core echo instruction. The original work observation still
has only its short report.

Typed success requires successful transport, valid declared output, unchanged
observed worksite and the exact task/transport relation. Source, candidate,
rubric and producer coordinates remain in that task; result matching checks
its complete input digest and raw output against the native observation.
Malformed or schema-invalid output, stale subject, mismatched task/provenance,
reused author invocation, failed native execution or observed edits yield
ordinary typed failure or admission refusal with available residue; they never
supply semantic acceptance.

NATIVEASSESS03 is an Executive-selected HOW refinement within Product's native
judgment/admission boundary and PAYLOAD-003/008/028 identity, provenance and
schema requirements. Those upstream grants require exact binding and declared
schema enforcement, not an LLM-authored digest echo. The retained NATIVEASSESS02
response remains rejected under its original consumer schema; this refinement
neither repairs that response nor supplies a new admission for its old Run.

The admitted observation and existing probabilistic transport evidence retain
the exact task, before/after observations and F_P provenance. The pure
`nativeWorkspaceAssessmentMatchesContext` relation verifies an assessment's
selected asset and workspace identities against a later observation; it does
not establish semantic truth or historical admission. A consumer must use the
admitted F_P result, preserve its provenance, validate currentness and declared
criterion coverage, and interpret its judgments through ordinary F_D and GTL
consequence. Neither structural validity nor an ordinary empty-gap report
substitutes for independent semantic evidence. No assessment file is written
into the reviewed worksite by this protocol.

Focused owner checks cover declaration/contracts, exact authority/pre-dispatch
freshness, actual partial edits on failure, malformed reports, scope/refusal,
read-only observations and touched-file currentness. They do not claim native
or installed end-to-end success. Installed consumer qualification must prove
initial false → native repair → independent evaluated true → terminal and
fresh ordinary result/replay. Model, effort, timers and budgets are unchanged.


## Native semantic source composition — selected 2026-09-24

It accepts only the declared native author/assessment graph, exact admitted actor/result/J and closed child; each consumer still checks its same-Run and current-subject conditions. The native work brief renders only the supported current task, source/current-asset paths, focused contract and (for the independent assessor) evaluation data. Internal computed semantic envelopes and native-basis proof bodies are not rendered or written as model input. The unique assessment schema owner comes from the authenticated execution closure, retaining exact installed publication and schema-byte checks.
