## Product Frame

ABIogenesis 5.0 is one source-independent installed Product for a trusted
developer desktop. GTL owns Program and GraphFunction definitions. Product
owns artifact verification, installation construction, catalog readiness, and
selection relations. Validator owns whole-Program judgment. HoG owns direct
traversal. ABG alone owns runtime admission and durable causal truth. Replay,

S1 establishes only a non-closing development relation corresponding to the
artifact portion of root obligation R1:

```text

  + exact Product manifest and content identities
  + exact one root-binding asset locator and asset digest
  + exact one matching module publication binding

  + installed documented Product verification export
  + the same explicit external artifact and basis

  -> stop before Product runtime
```

## Authority Equations And Seams

Let `CJ` be RFC 8785 canonical JSON UTF-8 bytes and `H` be SHA-256.

```text
RootDefinitionAuthority
  = exact bytes at package path contracts/abi5-root-binding.json

CandidateAuthority
  = assessor-frozen Abi5S1CandidateBasis
    + exact external tarball bytes

ProductVerification
  = verifyProduct(external artifactPath, artifactRef, basis identities)

RootReceipt
  = freeze(deriveRootReceipt(
      verified archive/manifest/content preimage,
      manifest-selected root asset bytes,
      exact-one matching publication binding))

InstalledSelection
  = package-installed documented Product export
    -> call verifyProduct on the same explicit external artifact/basis
    -> require Cut A/Cut B verified-artifact ref/digest/content equality
    -> rederive the byte-identical RootReceipt

    -> stop before Product resolve/install or runtime

  = reduce(CutA(ProductVerification, RootReceipt),
      CutB(ProductVerification, RootReceipt, InstalledSelection))
```

The seams remain separate:

1. The JSON carrier states root coordinates. It does not verify itself.
2. The manifest locates and digests that carrier. It does not restate its
   values.
3. The external basis identifies the candidate bytes an assessor selected. It
   does not become Product or runtime truth.
4. Product verification validates exact bytes and derives a receipt. It does
   not install, bind, admit a catalog, invoke, or append an event.
5. Offline package-manager extraction makes documented package exports
   importable. It is not Product resolution, R2 Product installation, ABG
   admission, or durable truth.
6. `ProductInstall`, Catalog, Validator, `ExecutionBasis`, owner execution,
   ABG, replay, and CLI outcome remain later executable/runtime joins.
7. The S1 reducer reports a development gate only. It cannot call or impersonate
   the full root governor.

## Product Verification And Internal Receipt

For an exact ABI Product, the existing `verifyProduct` pipeline performs the
root stage after archive safety, manifest, payload inventory, Product content,
and contribution coherence checks and before minting the existing
`VerifiedProductArtifact.verificationDigest`.

The root stage requires:

```text
assetBytes = CJ(strictShapeParse(assetBytes))
H(assetBytes) = manifest.rootBindingAsset.contentDigest
manifest.rootBindingAsset = basis.rootBindingAsset             [S1 proof]
manifest digest = basis.product.manifestDigest                  [S1 proof]
Product content digest = basis.product.productContentDigest     [S1 proof]
exactly one contributionManifest.publicationBindings row equals
  parsedRootBinding.publicationBinding.{moduleRef, publicationDigest}
selected publicationDigest = basis.publication.publicationDigest [S1 proof]
contributionManifest and verified package owner coordinates equal
  parsedRootBinding.publicationBinding owner coordinates
```

It does not import GTL, construct a Module, validate a Program body, decide
callability, inspect a leaf, construct a catalog, or emit an ABG event.

The private Product stage derives one
`Abi5RootBindingVerificationReceipt` containing only:

```text
kind, schemaVersion, disposition
artifactRef, artifactDigest
productId, packageName, packageVersion
productContentDigest, manifestDigest
rootBindingAsset
parsed root-binding coordinates
the unique selected moduleRef + publicationDigest binding and owner coordinates
receiptDigest, receiptRef
```

`receiptDigest` is `H(CJ(receipt body without receiptDigest and receiptRef))`.
The receipt is deeply frozen. It excludes the enclosing verification ref and
digest, avoiding a digest cycle.

The exact Public `product.verify#verify` result stays unchanged. The receipt is
not added to `PublicOutcome`, `VerifiedProductArtifact`, resolved lock,
installed record, `ProductInstall`, workspace binding, catalog, invocation,
ABG event, replay, or any store. During ordinary verification, the private
receipt authorizes completion of the existing verification pipeline and is
then discardable.

Installed Product code exposes a relational S1 verifier that accepts the exact
external `artifactPath`, `artifactRef`, and admitted candidate basis. It calls
the existing `product.verifyProduct` with the basis-derived expected artifact,
Product, package, content, and manifest identities, rederives the same private
receipt from the exact archive/manifest/asset/publication preimage, and returns
the pair as internal evidence. The exact Public result remains coordinate- and
content-identity evidence only: it gains no receipt. No Public request or
result contract changes.

A structural predicate for the receipt checks shape and self-digest only. It
cannot authenticate a self-consistent forgery. The relational verifier accepts
the candidate receipt only together with the exact artifact bytes, manifest
bytes, root asset bytes, contribution manifest, and external basis; it reruns
the complete relation and requires byte-for-byte equality with the rederived
receipt.

## Two-Cut Acceptance And Causally Prior Selection

S1 acceptance has exactly two cuts.

Together they are the bounded two-step realization of existing Constitution
join `J01`: Cut A freezes the verified-artifact coordinate plus the transient
receipt ref/digest from the prebuilt bytes; Cut B joins that coordinate to
package-installed Product bytes through `verifyProduct`. S1 does not enter
`J02` or `X02`.

### Cut A — Prebuilt Artifact Verification

```text
explicit external artifactPath + artifactRef + admitted basisPath
  -> assessor's isolated read-only extraction imports the documented Product export
  -> existing product.verifyProduct over the prebuilt tarball
  -> exact artifact/Product/content/manifest/root/publication checks
  -> full VerifiedProductArtifact + private RootReceipt
  -> retain transient receipt body; freeze verification + receipt coordinates
```

Cut A imports no candidate-checkout or private module. Its read-only assessor
extraction is not package-manager or Product installation. Cut A does not
build, pack, resolve, bind, admit, view, invoke, append, replay, or call a
governor. The private receipt is transient evidence alongside the full Product
verification result. Only its ref/digest may enter the external gate result;
its body is not put in the exact Public result or a durable carrier.

### Cut B — Fresh Offline Package Consumer

```text
fresh empty offline package-manager host
  -> npm install --offline --ignore-scripts <frozen artifactPath>
  -> import documented @abiogenesis/typescript-tenant/product exports
  -> installed Product calls verifyProduct with the same explicit
     artifactPath + artifactRef + admitted basis
  -> Cut B full verified-artifact ref/digest/content identities equal Cut A
  -> installed package manifest/root-asset/publication bytes rederive the
     byte-identical RootReceipt
  -> derive and freeze Program/GF/contract/module-publication/owner selection
     coordinates only from that receipt
  -> stop
```

Package-manager extraction is only the physical act that makes documented
exports importable. It is not `product.resolve`, `ProductInstall`, R2 Product
installation, workspace binding, ABG admission, or evidence for any of them.
Cut B stops before Product resolve/install, catalog admit/view,
`ExecutionBasis`, GraphFunction invocation, owner execution, any ABG append,
replay/CLI outcome, or the root governor.

Full Cut A/Cut B `verifyProduct` identity equality is required before the
receipt may construct the selection. The exact coordinate-only Public
`product.verify#verify` result remains unchanged and must project those same
verification/artifact/Product/content coordinates whenever an already-lawful
integration path invokes it. S1 does not invent a `DefinitionCall`, capability
grant, or transport authority to manufacture that Public outcome. If no such
already-authorized Public outcome is supplied as independent evidence, Public
equality remains an integration invariant and S1 consumes the full installed
`verifyProduct` result; it claims no dynamic Public invocation.

Cut B receives no Cut A receipt body. The assessor compares the independently
rederived Cut A and Cut B outputs, and the selection constructor consumes only
Cut B's relationally authenticated receipt after that equality succeeds. There
is no hidden receipt transport between cuts.

The root selection constructor accepts only a relationally rederived receipt.
It has no fallback Program, GraphFunction, contract, module-publication, owner,
or compute-regime constant. Missing, forged, stale, or crossed evidence refuses
before selection construction. This makes the carrier causally necessary at
the first lawful pre-use seam without importing S2 or constitutional runtime
authority.

`Abi5S1RootSelection` is the deeply frozen ephemeral projection of
`receiptRef`, `receiptDigest`, binding/governor/scenario, declared target
boundary/runnable/outcome, module publication and owner, Program,
GraphFunction, contracts, traversal declarations, and compute regime. Its
`selectionDigest` is `H(CJ(body without selectionDigest and selectionRef))` and
its `selectionRef` is
`s1-root-selection://abiogenesis/<selectionDigest hex>`. Only its ref/digest
enter the S1 result. It is not added to a lock, Product install, catalog,
request, event, replay, store, or governor input.

Existing `root-owner-evidence.mjs`, catalog/`ExecutionBasis` equality,
owner execution, ABG, replay, CLI outcome, and the full root governor may later

## Source-Blind Freeze And Proof Procedure

The proof has four ordered phases.

1. **Construct candidate.** Start from the accepted docs head whose Product
   bytes remain `v5.0.0-dev.286`. Implement only the selected design, migrate
   all version-bearing surfaces to `5.0.0-dev.288`, refresh owned generated
   assets, commit, and record the exact candidate commit/tree. The checkout
   must be clean.
2. **Build and pack once.** On that clean exact candidate, run the clean
   candidate build exactly once. Confirm the build causes no tree change. Run
   `npm pack --ignore-scripts --json` exactly once so pack cannot rebuild.
   Move the tarball and raw pack record outside the checkout.
3. **Assessor freeze.** An independent assessor reads the external tarball,
   exact Git commit/tree, packed manifest, root asset, publication, and pack
   record. The assessor first admits the carrier's closed shape and compares
   its complete semantics with the Product root table, then accepts only the
   resulting asset/publication digests into the basis. It constructs
   `Abi5S1CandidateBasis`, computes its content address, and freezes it beside
   the tarball outside the checkout. It never copies the semantic coordinates
   into the basis. A rejected basis is never overwritten.
4. **Two-cut proof.** Cut A invokes existing Product verification against the
   prebuilt external tarball and basis, freezes the verification identities and
   receipt ref/digest while keeping the receipt body transient, and stops. Cut
   B creates a fresh empty offline package-manager host,
   extracts only the frozen tarball with scripts disabled, imports documented
   Product exports, reruns verification from the same explicit inputs, requires
   Cut A/Cut B identity and receipt equality, constructs the receipt-derived
   root selection, and stops. Neither cut reads candidate source or test
   fixtures, performs a private import, uses an ambient fallback, or runs a
   build or pack. Neither cut performs Product resolve/install or any runtime
   operation.

No proof step may write the candidate checkout, tarball, or basis. A test that
generates its own candidate basis, derives expected identities from the
artifact under test, uses `candidateBasisSource: "packed_artifact"`, or falls
back to a source fixture is invalid proof.
