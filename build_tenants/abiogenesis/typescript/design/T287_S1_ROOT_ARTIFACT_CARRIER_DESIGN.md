## Product Frame And S1 Claim

ABIogenesis 5.0 is one source-independent installed Product for a trusted
developer desktop. GTL owns Program and GraphFunction definitions. Product
owns artifact verification, installation construction, catalog readiness, and
selection relations. Validator owns whole-Program judgment. HoG owns direct
traversal. ABG alone owns runtime admission and durable causal truth. Replay,
Public, SDK, CLI, tests, and governors are projections, transports, or proof
consumers; none becomes another semantic or runtime authority.

S1 proves one non-closing development relation over an exact prebuilt
candidate: the packed Product carries exactly one digest-bound ABI root
definition, exactly one owner-bound module publication matches its declared
`moduleRef`, Product verification derives one private receipt, and an offline
package-manager extraction re-verifies the same bytes before lexically issuing
the root selection. That is development evidence for the artifact portion of
R1. It is not constitutional R1 satisfaction because its subject is
`s1_development_candidate`, not `pre_rc_candidate`.

The carrier may declare the exact Product-root Program, GraphFunction, input
contract, output contract, one-callable/all-`F_D` target, runnable form, and
terminal outcome. S1 proves only that those declarations are present in the
one accepted carrier and bound to one exact publication. It does not prove
callable membership or cardinality, a `ProgramValidation` body, materialized
graph validity, an actual all-`F_D` traversal, owner execution, a terminal
result, replay, CLI equality, or any compute regime. Those truths remain with
R5 Program selection/admission, R6 GraphFunction and contract resolution, R7
graph materialization/validation, R8 traversal entry, R9 causal result/closure,
and R10 replay/CLI equality on an exact `pre_rc_candidate`. S1 closes none of
R1 through R10.

S1 acceptance has exactly two cuts:

```text
Cut A: explicit frozen tarball + artifact ref + admitted external basis
  -> existing Product verify owner
  -> pure root-preimage verification
  -> verification coordinate + private receipt coordinate

Cut B: fresh offline package-manager extraction + the same explicit inputs
  -> installed documented Product export
  -> Product re-verification + complete extracted-byte observation
  -> exact Cut-A coordinate equality + private receipt rederivation
  -> lexical root selection
  -> stop before Product runtime
```

Neither cut resolves or installs a constitutional Product, constructs a lock,
admits `ProductInstall`, binds a workspace, constructs or narrows a Catalog,
admits a Program, constructs an `ExecutionBasis`, invokes a GraphFunction or

governor. Package-manager extraction is proof-host preparation, not R2 Product
installation.

```text
  = coordinate(freeze(deriveReceipt(VerifiedAbi5RootPreimage)))

      verificationRequest,
```

`publicationDigest` and the artifact owner tuple do not occur in `B_root`.
They are derived only after `Q` is fixed. The existing contribution binding
carries `P`; the verified package/manifest context carries `OwnerTuple`; and
the external candidate basis, private receipt, and selection bind both. This
removes the impossible cycle
`P = H(... H(root-with-P) ...)`. The root JSON also contains no package name,
package version, Product id, or publisher namespace. Package and manifest own
those facts.

The seams remain distinct:

1. The root JSON is the sole full semantic definition. It does not verify
   itself or identify an artifact owner.
2. Valibot admits a strict closed shape only. It does not authenticate the
   intended semantic values.
3. Canonical bytes and independently frozen digests authenticate the intended
   carrier instance.
4. The manifest locates the carrier and binds it to the Product inventory. It
   does not restate the carrier body.
5. After Product content is fixed, the existing publication owner derives its
   unchanged digest and Product separately projects the verified manifest
   owner tuple. Neither enters the root JSON.
6. The external basis identifies the exact development candidate selected by
   an independent assessor. It is not Product or runtime truth.
7. Product verification derives an internal receipt from exact bytes. A shape
   predicate or self-consistent caller object authenticates nothing.
8. Cut B observes installed bytes and rederives the receipt before it can issue
   a selection. It does not create a Product install or runtime authority.

## Manifest, Inventory, And Publication Law

For the current allocation, the exact ABI Product predicate is:

```text
packageName    = @abiogenesis/typescript-tenant
packageVersion = V_alloc
productId      = product://abiogenesis/typescript-tenant@V_alloc
```

The manifest contract is conditional and closed:

```text
exact ABI Product at V_alloc
  => exactly one dedicated rootBindingAsset locator
  => exactly one reserved carrier across the complete packed payload inventory
  => exactly one matching module publication selected by moduleRef + OwnerTuple

every non-ABI Product
  => zero rootBindingAsset locators
  => zero reserved ABI root carrier payloads
  => zero ABI root receipts and selections
```

An unrelated or dependency Product with no locator remains valid. Copying the
locator or carrier into a non-ABI Product refuses before receipt construction.
A product-id prefix, caller flag, optional mode, dependency identity, first
match, or ambient package identity cannot activate the ABI branch.

The dedicated `rootBindingAsset` uses the existing `ProductAssetLocator`
mechanics and records only package-relative path, JSON media type, carrier
schema version, and `D_root`. The root bytes participate in `Q`; the locator
and derived publication binding participate in `M`. The generator inventories
and hashes the checked-in file but never authors or rewrites it.

Sole-carrier enforcement scans the complete regular-file payload census, not
only the manifest locator. Every payload that parses as the reserved strict
root-carrier shape is counted. A payload that claims the reserved carrier kind
but is malformed is a reserved-carrier refusal, not an unrelated JSON file.
The ABI branch requires a count of one and requires the manifest locator to
name that same canonical byte sequence. A second valid carrier refuses even
when unreferenced. The non-ABI branch requires a count of zero. Symlink,
traversal, duplicate-path, noncanonical-byte, unreadable-payload, and digest
checks stay with existing Product archive and manifest owners.

After `Q` is fixed, Product constructs module publications through the existing
generator path. The root-binding seam passes the verified manifest publication
bindings to existing `product/exact_match.ts::resolveExactMatch`; it adds no
publication resolver. Exact-one root publication selection uses:

```text
publication.moduleRef = carrier.moduleRef
publication owner     = OwnerTuple derived from verified package + manifest
```

`moduleRef` is the only publication-relation coordinate in the root JSON; the
rest of the JSON still carries the fixed Product root-table semantics. After
`resolveExactMatch` returns exactly one contextualized manifest binding,
Product uses the existing unchanged publication constructor/digest, requires
the binding row to contain the same `P`, and requires its enclosing verified
package/manifest owner context to equal `OwnerTuple`. The external basis
independently pins `P` and `OwnerTuple`. Matching `moduleRef` alone is
insufficient; wrong publisher, Product, package, version, duplicate owner row,
or crossed digest refuses. No root-specific digest wraps or changes the
existing publication digest.

`verifyAbi5RootBindingPreimage` is the named pure owner-boundary seam. It is
not exported as a receipt constructor. Its inputs are exact bytes and admitted
coordinates, not a structurally plausible receipt:

```ts
verifyAbi5RootBindingPreimage({
  verifiedArtifact,
  canonicalManifestBytes,
  completePayloadInventory,
  rootBindingBytes,
  matchingPublicationBytes,
  expectedRootCarrierDigest,
  expectedPublicationDigest,
}): VerifiedAbi5RootPreimage | Abi5S1PrivateRefusal
```

It proves, in order:

1. the existing `VerifiedProductArtifact` identities equal the exact
   `VerifyProductRequest`; proof support separately derived that request from
   the admitted basis;
2. manifest bytes are canonical and hash to the verified `M`;
3. the complete packed inventory hashes to `Q` and has the conditional
   ABI/non-ABI carrier cardinality;
4. the manifest locator selects the sole canonical `B_root`, whose `D_root`
   equals the independently supplied `expectedRootCarrierDigest`;
5. `B_root` passes strict closed-shape admission without treating shape as
   authenticity;
6. exactly one publication matches `carrier.moduleRef + OwnerTuple`;
7. its derived `P` equals the manifest binding and independently supplied
   `expectedPublicationDigest`; and
8. all artifact, Product, manifest, contribution, root, publication, and owner
   coordinates form one preimage.

Only this success branch produces the module-private branded
`VerifiedAbi5RootPreimage`. The brand has no public constructor, parser,
serializer, assertion function, or declaration export. A caller cannot submit
a receipt or brand. The receipt derivation closes lexically over the branded
value. Structural receipt predicates, self-digests, and mutually consistent
caller fields authenticate nothing.

The internal `Abi5RootBindingVerificationReceipt` binds the verification
coordinate, artifact ref/digest, package/Product/content/manifest/contribution
identities, root locator/digest, carrier semantic projection, derived
publication digest and OwnerTuple, and receipt ref/digest. It is deeply frozen.
Its body never leaves the Product lexical scope and is never written into a
lock, `ProductInstall`, Catalog, invocation, ABG event/log, replay, CLI
transcript, fixture, store, or test snapshot. Only
`{receiptRef, receiptDigest}` crosses Cut A.

Ordinary `verifyProduct` failures preserve the existing exhaustive Product
refusal codes and bodies:

```text
artifact_unreadable | artifact_digest_mismatch | manifest_unreadable |
manifest_malformed | manifest_digest_mismatch | identity_mismatch |
unsafe_locator | payload_inventory_mismatch | payload_unreadable |
product_content_mismatch | contribution_mismatch | catalog_mismatch |
contract_asset_mismatch
```

No root-specific code is added to the exact Public contract. New S1 codes are
private proof diagnostics. When the owner refuses, S1 preserves the complete
owner refusal and adds only its private boundary label; it never collapses or
renames the Product code.

The unchanged `verifyProduct` wrapper runs the same packed/root relation for
the exact ABI branch, internally derives the receipt needed to accept that
branch, and discards the private body before returning its existing full
artifact projection. Root failures map through existing exhaustive owners:
locator shape/cardinality to `manifest_malformed`; packed carrier
cardinality/path to `payload_inventory_mismatch` or `unsafe_locator`;
unreadable/digest/content mismatch to `payload_unreadable` or
`product_content_mismatch`; and publication/owner/digest mismatch to
`contribution_mismatch`. The S1 port can retain a more precise private
diagnostic without changing that Public mapping.

## Cut A — Frozen Artifact Verification

Cut A consumes only explicit paths/refs admitted by the external run basis. It
imports one documented `./product` port from the assessor-frozen, read-only
Cut-A package root whose complete payload bytes are bound to the same tarball.
The Product surface is exactly one frozen port object with two fixed methods:


The object is the one new documented `./product` export. Its two fixed methods
are the irreducible packed-only and installed-byte joins; they are not an
optional mode, generic proof adapter, Public operation, or runtime selector.
Both request objects receive strict closed admission; an unknown receipt,
carrier, basis, selection, mode, or runtime field is a typed S1 input refusal,
not an ignored argument.
The inner packed/installed observers, preimage brand, receipt derivation, and

The external assessor admits the basis and derives
`verificationRequest`, `expectedRootCarrierDigest`, and

or understand `Abi5S1CandidateBasis`.

`verifyPacked` executes:

```text

  -> unchanged VerifiedProductArtifact projection
  -> preserve any exact Product refusal
  -> exact sole root carrier + resolveExactMatch publication binding
  -> compare independently supplied root/publication digests
  -> verifyAbi5RootBindingPreimage
  -> derive private receipt
  -> return unchanged verified artifact + verification/receipt coordinates
```

`observePackedProductPayload(request)` is the internal factor of the existing
Product verifier. It consumes the archive reader's one `payloadFiles` byte map;
root checks reuse those bytes and never reopen/re-read the payload. Existing
`verifyProduct` calls that factor and returns the same full
`VerifiedProductArtifact` or exact Product refusal. Cut A does not return a
receipt body or selection. The artifact's `verificationRef` and
`verificationDigest` form the Cut-A coordinate. Root validation and private
receipt derivation add no field or refusal code to the exact Public result.

## Cut B — Installed-Byte Equality And Lexical Selection

Cut B imports the same documented port through the installed package's
documented `./product` export and calls exactly
`ABI5_S1_ROOT_CARRIER_PORT.verifyInstalledAndSelect` with the signature above.

There is no overload and no argument for a receipt body, carrier body,
selection, expected Program/GF/contract constants, assessor basis, source root,
fixture, Catalog, lock, `ProductInstall`, `DefinitionCall`, grant, or ABG
state.

The method is one lexical Product composition:

1. Admit/confine inputs and load the port through the installed documented
   export; reject deep/private/source/ambient resolution.
2. Call `observePackedProductPayload(verificationRequest)`, preserving any
   ordinary Product refusal, and locally project the unchanged reverified
   artifact.
3. Require its `{verificationRef, verificationDigest}` to equal
   `expectedCutA.verifiedArtifactCoordinate` before any private receipt is
   derived or used.
4. From the same packed byte map, require exactly one reserved root carrier,
   require its digest to equal `expectedRootCarrierDigest`, select exactly one
   owner-bound manifest publication through `resolveExactMatch`, and require
   its digest to equal `expectedPublicationDigest`.
5. Construct a closed `ProductPayloadExpectation` from those verified packed
   bytes and call
   `observeInstalledProductPayload(installedPackageRoot, expectation)`.
6. Require complete package.json, canonical manifest, capability graph asset,
   root asset, contribution binding, and payload inventory byte equality.
7. Invoke `verifyAbi5RootBindingPreimage` over the locally observed exact
   packed and installed bytes, derive a new private receipt, and require only
   its coordinate to equal `expectedCutA.rootReceiptCoordinate`.
8. Project `Abi5S1RootSelection` directly from the local branded preimage and
   receipt, then make the brand and receipt body unreachable before return.

`ProductPayloadExpectation` is a closed Product-internal byte expectation: the
verified package name/version/Product id, canonical manifest bytes/digest,
capability graph locator/bytes/digest, root locator/bytes/digest, contribution
publication binding, `productContentDigest`, and the exact sorted
`productRelativeLocators` path/bytes/digest rows. It contains no lock,
`ProductInstall`, ABG, or runtime type. Existing Product inventory law requires
those rows to include `package.json`, the root carrier at its exact locator,
and every other ordinary package payload not owned by the separately named
manifest/capability-graph entries. The separately named root fields must point
to that one inventory row. An expectation with an omitted or duplicate row, an
overlap with either separately inventoried manifest/graph entry, or a crossed
root row refuses before the installed filesystem is read.

`code/src/product/installed_payload_observation.ts` owns the read-only
`observeInstalledProductPayload(installedPackageRoot, expectation)` factor. It
recurses from `installedPackageRoot` itself, rejects every symlink, unexpected
node kind, unsafe path, missing expected file, duplicate, and extra top-level
or nested file, and requires the complete file set to be exactly:

```text
product-toolchain-manifest.json
capability graph asset locator
every productRelativeLocators entry
```

It reads each payload file exactly once and reuses those bytes for canonical
manifest parsing, package identity, inventory, root asset, capability asset,
contribution binding, and digest equality. It performs no write and imports no
`ResolvedProductLock`, `ProductInstall`, or ABG type. Existing
`installedProductContentMatches` becomes only a Boolean compatibility
projection over this typed observation/refusal. The observer returns:

```text

  installedPayloadInventoryDigest,

  contributionManifestDigest, publicationDigest, OwnerTuple

```

or one typed read/confinement/identity/inventory refusal. Its coordinate is
content-addressed; the machine realpath is evidence, not Product identity.

`CutBSuccess` contains only the Cut-B verification coordinate, installed
observation coordinate, receipt ref/digest, and the immutable
`Abi5S1RootSelection`. The selection declares the carrier's binding, module,
Program, GraphFunction, and contract coordinates and binds them to `P`,
OwnerTuple, `D_root`, and its own ref/digest. It claims no callable membership,
validation, traversal, or runtime result.

There is no public `selectRoot(receipt)` or receipt rehydrator. The one
documented enclosing port method is exported; receipt derivation and
receipt-to-selection construction are module-private and share one lexical
closure over the opaque verified preimage. This is the canonical Product

this seam before its Catalog request; production may not retain a hard-coded,

construction and stops before that later use.

The exact Public `product.verify#verify` result remains unchanged. S1 neither
constructs a Public invocation nor mints a capability grant or
`DefinitionCall` to obtain one. If a lawful Public verification outcome exists
in a later integration or root regression, its projected verification

the selection can be used. That equality is an integration invariant, not an
S1-created outcome or transport authority.

## Source-Blind Freeze And Proof Procedure

The assessor executes the following immutable sequence:

1. **Clean candidate.** Start from the accepted docs basis and the allocated
   implementation version. Require the intended candidate commit/tree and a
   clean tracked tree.
2. **Build once.** In the candidate checkout, run the accepted clean build
   exactly once. No proof begins yet.
3. **Pack once.** Run the accepted pack exactly once and record npm filename,
   byte length, SHA-1 shasum, SHA-512 integrity, and SHA-256.
4. **Independent freeze.** Move/copy the immutable tarball to an external
   read-only proof root. An independent assessor reads the bytes, performs the
   semantic assessment, and freezes `Abi5S1CandidateBasis`, one complete
   `Abi5S1ProofBundleManifest` with driver/load-hook/dependency/snapshot bytes,
   and one `Abi5S1ProofRunBasis`. Candidate tests may inform this freeze but
   are not part of the mounted proof.
5. **Prepare distinct hosts and remove source.** Raw-extract the frozen tarball
   into Cut A's otherwise empty
   `node_modules/@abiogenesis/typescript-tenant` without running package
   scripts. Before Product import, the frozen proof driver compares the exact
   regular-file inventory and bytes of that root to the tarball inventory;
   loaded-module digests must also equal those rows. Unmount or make unreadable
   the candidate checkout,
   source, tests, fixtures, build scripts, user home, ambient caches, global
   modules, and network. Verify realpath confinement and empty controlled
   home/cache/config/prefix/module paths. Activate the frozen ESM hook and
   verify every loaded URL against the allowed realpath roots.
6. **Cut A once.** Through the Cut-A package's documented `./product` export,
   call `ABI5_S1_ROOT_CARRIER_PORT.verifyPacked` with the basis-derived
   verification request and expected root/publication digests. Freeze the
   unchanged verified artifact plus verification and receipt coordinates; no
   receipt body leaves the method.
7. **Fresh offline host.** Create a distinct empty HOME/cache/config/consumer
   root and use the pinned npm version with
   `--offline --ignore-scripts --no-audit --no-fund --omit=dev` to install the
   exact local tarball from the frozen closure. This npm filesystem action is
   not Product resolution, lock construction, R2 installation, or ABG
   admission. For an installed-root negative snapshot only, the frozen proof
   driver may now apply its one declared mutation inside assessor scratch,
   record exact before/after inventory coordinates, and remount the root
   read-only. Positive roots remain untouched; no mutation occurs after Cut B
   begins.
8. **Cut B once.** Through that installed package's documented `./product`
   export, call `ABI5_S1_ROOT_CARRIER_PORT.verifyInstalledAndSelect` with the
   same basis-derived verification request/digests, explicit
   `installedPackageRoot`, and the two Cut-A coordinate pairs. The cut is
   read-only and stops at the returned selection.
9. **Freeze result.** Record one exact union variant and all external file and
   output hashes. A success result claims only the S1 development gate.

Inside the proof there is no build, pack, generation, basis refresh, source or
private import, candidate test read, package-root inference, ambient fallback,
network lookup, Product resolve/install, ABG action, root evaluation, or
runtime execution.

## Pure Owner-Boundary And Fault-Injection Matrix

Before bundle freeze, candidate-owned co-located tests call the named
module-private seams with typed fault injection. The independent assessor runs
that source-input evaluation once, binds its exact production-module digest,
and freezes only the canonical input/output snapshots and mutation definitions
into the external proof bundle. Source-blind qualification re-admits those
frozen snapshots and module identity; it does not mount or read the candidate
tests, import a private Product module, or expose a proof-only production port.
This lane proves inner branches without pretending a broken outer artifact
reached them. It supports but does not replace representative end-to-end
snapshots `S1-E00`, `E01`, `E03`, `E05`, `E07`, `E09`, `E10`, and `E13`.

## Delivery State Machine

Delivery has exactly four rows. The delivery owner derives, rather than
mutates, the allocation ledger from immutable remote Product tags plus
create-only implementation-rejection archives. Each rejection archive has a
strict metadata record binding its allocated version to its commit/tree,
artifact, bases, result, and verdict. `V_alloc` is the least unused development
version greater than every tagged or rejection-archived version; docs archives
do not enter that projection. The remotely archived `dev.287` rejection makes
the current value `5.0.0-dev.288`; `T_alloc = v${V_alloc}`. Main and every
Product tag remain stable while either candidate is constructed or reviewed;
only the applicable post-verdict row may move a delivery ref.

| Subject/verdict | Required transition | Main/tag/version result | Evidence/archive result |
|---|---|---|---|
| docs accepted | after verdict, use an expected-old-OID local ref transaction to fast-forward `main`, then an expected-remote-old atomic push of `main`; accepted state requires local/remote equality | main advances only; no Product tag; no version burn; `V_alloc` remains available | preserve docs commit/tree/verdict identity |
| docs rejected | create only the immutable archive ref with expected absent/old OID and publish that ref without touching delivery refs | main and Product tags unchanged; no Product version burn; `V_alloc` unchanged | archive docs commit/tree/verdict; archive is evidence, never donor authority |
| implementation accepted | after independent reproduction and `evidence_complete`, create annotated `T_alloc`; use one expected-old-OID local transaction for main+tag+create-only archive refs and one atomic remote push of those refs with expected remote OIDs; completion requires exact local/remote equality | main fast-forwards and exactly one immutable annotated tag appears at `V_alloc`; no partial accepted state | archive commit/tree, tarball, candidate basis, proof bundle/run basis, load census, snapshots/result, and verdict; tag message records every external ref/digest |
| implementation rejected | publish only the version-bound create-only archive with expected-absent OID; confirmed remote containment deterministically changes the allocation projection | main and existing Product tags unchanged; archived `V_alloc` is permanently burned; next attempt receives the least unused development version | archive commit/tree, tarball, candidate basis, proof bundle/run basis, load census, snapshots/result, and rejection verdict |

Every local multi-ref change uses one `update-ref` transaction with explicit
expected old OIDs; every remote multi-ref publication uses atomic push plus
explicit lease/expected OIDs. A mismatch refuses before ref movement. If a
docs-accept remote publication fails after local preparation, the expected new
main OID permits exact main rollback. If an implementation-accept remote
publication fails, exact rollback restores main only; the prepared annotated
tag and create-only archive remain immutable local evidence pending retry and
have no delivered status until remote containment. Partial state cannot be
reported as delivery.

Archive refs are create-only. They are never reused, force-moved, or deleted.

No tag is created for docs. Tags are immutable and never moved or repaired. If
current `dev.288` implementation fails, its
archive remains evidence and `dev.289` becomes the next allocation without a
schema edit. A docs commit, candidate commit, local branch, review, test count,
or green source-tree run is not delivery.

## Acceptance And Stop Conditions

S1 may pass only when one exact external candidate basis, proof bundle
manifest, and proof run basis, one once-built/once-packed tarball, one Cut-A
coordinate pair, and one fresh offline installed-root observation produce
equal Cut-B verification/receipt coordinates, two confined ESM load censuses,
and one lexical selection, while every prohibited-effect counter is zero. The
result must be the closed `evidence_complete` variant with
`rootQualification = not_evaluated` and
`advancementAuthorization = none`; all concrete negative snapshots must
refuse at their owning boundary.

Stop and return to the owning re-entry if implementation requires any of the
following:

- a second full root-definition constant, generated carrier, or fixture truth;
- `publicationDigest` or an artifact-owner tuple inside the root JSON;
- a receipt body in Public, lock, install, Catalog, invocation, ABG, replay,
  CLI, store, event, or durable handoff;
- a public receipt constructor, receipt-taking selector, structural
  authentication, coordinate-only receipt magic, or caller-minted brand;
- source/private imports, test-generated basis, build/pack in proof, ambient
  fallback, network, or unconfined package resolution;
- Product resolve/install, Catalog/View, Program admission/validation,
  `ExecutionBasis`, invocation, ABG, replay, CLI, or eligible/full
  root-governor evaluation in either qualification cut; implementation and
  pre-freeze proof of the outer subject guard are the sole governor exception;
- a callable-membership, all-`F_D`, ProgramValidation, runtime, R1, scenario,
  pre-RC, qualification, or release claim;
- a new library, Effect runner/lift, controller, registry, second catalog,
  source loader, event writer, store, universal carrier, or parallel root
  selector; or
- delivery that edits main/tag before verdict, creates a docs tag, reuses a
  rejected implementation version, moves an immutable tag, or omits the
  external evidence archive.
